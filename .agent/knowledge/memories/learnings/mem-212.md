# Learning: Anthropic Admin API cannot mint API keys: /v1/organizations/api_keys is list/ret

## Summary
Anthropic Admin API cannot mint API keys: /v1/organizations/api_keys is list/retrieve/update only and no endpoint ever returns a key value (partial_key_hint only); keys are created in the Claude Console by a human. Verified 2026-10-05 on the live reference while specing TASK-502 leg 1, whose plan said 'workspace + key per org via Admin API'. Workspaces CAN be created/archived and keys CAN be deactivated (status=inactive) programmatically, so a per-tenant key design must be a human-minted pool (console assigns, deactivates, warns on low) or Workload Identity Federation (service accounts + federation rules, OAuth org:admin only, needs an OIDC issuer). Founder chose the pool (console#353/#354/#355). Check the live Admin API reference before any plan that says 'create a key programmatically'.
