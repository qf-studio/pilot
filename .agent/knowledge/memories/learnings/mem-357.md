# Learning: Review after a merge, limits of a mutation run (2026-11-27): the session reviewe

## Summary
Review after a merge, limits of a mutation run (2026-11-27): the session reviewed two SDK pull requests for a Plane poller option with mutations, each mutation failed the right test, and the verdict was no finding. The daemon's own review then found that the same tests gave their result by timing: the test helper cancelled the poller context at an early signal (the done label), before the last asserted request (the state update) left. A mutation that fails the right test one time does not prove that a test is free of timing. For a test that stops a loop or a poller by a signal, check that the signal comes after the last asserted effect in the code order, and run the test 20 times with the race detector. Two more rules of that day: a scripted mutation counts only when the script reports that it changed the file and the failed test is the intended one; and a ticket that adds an option must name the production caller path (the option was added to the poller, and the daemon builds the poller through the adapter, which made its own option list).
