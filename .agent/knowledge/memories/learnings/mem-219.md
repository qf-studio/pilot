# Learning: Prod test-org discipline — never terminate (retires the pool key), one browser = one org, and read SSM/EC2 instead of the SPA when it freezes

## Summary
Rules learned while running TASK-513 on two prod test orgs: (1) never deprovision a test org — `reapPlatformKey` deactivates its lent pool key at Anthropic for good; stop is not available from the UI (console#371); (2) the console session is per browser, so with two orgs the Connections page looks identical and a credential save lands on whichever org is logged in — check the pool-key label on the card or the SSM `LastModifiedDate` under `/tenants/<org>/`; (3) the SPA freezes long-lived tabs (ui#206) — verify state via `aws logs tail /pilot-fleet/console-reconciler`, `aws ec2 describe-instances --filters Name=tag:pilot:org_id,…`, and `aws ssm send-command` on the tenant box (`journalctl -u pilot`), all with profile `quantflow`.

## Context
2026-10-07/08 TASK-513. The first own-key save hit the wrong org (Testica instead of Test 2) because the browser session had not been switched; the console showed the false "Saved credential missing from store" warning either way (console#374). The SPA froze the Chrome renderer five times; every verification after that came from AWS.

## Details
Useful facts for the next prod test: `POST /api/v1/instances/provision` and `PATCH /api/v1/connections/{tracker}` need `X-Requested-With: pilot-console`; PATCH takes `{config:{repos:[…]}}` without the token (used to fix a trailing-comma repo entry). An `error` row (`observed_state=terminated`) does not block a new claim. The founder box does not poll `pilot-canary-sandbox`, but two tenant boxes watching the same repo with the same label do race — swap one org's repo (e.g. `qf-studio/pilot-e2e-fixture`) before filing. Usage poll is every 15 min; resume after an own-key save took 36 s; a provision on a clean path took ~50 s to `running` and ~5 min to configured.

## Recommended Approach
Before a prod test: write the org ids and box ids into the task doc; log out between orgs; use `/billing` (not `/instances`) for API fetches from the SPA; keep the Anthropic usage page (platform.claude.com → Usage, workspace `pilot-pool-0N`) as the spend oracle.
