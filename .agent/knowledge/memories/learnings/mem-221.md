# Learning: Review-wave loop: post-merge review → nav-research briefs → filed issues → merged in 30 min → reviewed with pins

## Summary
On 2026-10-08 two full waves (5 + 5 PRs across pilot-console-ui and pilot-console) went review → research → file → merge → review in one session; the key accelerators were two navigator-research briefs that verified every path with git cat-file before the issue bodies were written, and no-decompose + H2 headers on every issue.

## Context
Gap wave (ui#205-207, console#373-374) and follow-up wave (ui#211-213, console#377-378). All 10 merged by hosted autopilot; 10 review comments posted. One hold (GH-205, cross-repo docs path in body) and one conflict (PR#376, two EOF test appends) were the only friction.

## Details
Timing: issues filed ~12:21Z, all five PRs merged by 12:47Z. Pre-flight that prevented holds: extract every backticked span containing '/' with a dot after the last slash and check 'git cat-file -e origin/main:<path>' in the TARGET repo. Conflicts between sibling PRs in the same file (handlers_test.go) are mechanical when both append at EOF: merge origin/main in a temp worktree, push; autopilot re-adopts via the GH-4610 path within one poll.

## Recommended Approach
For a review-driven wave: (1) review merged PRs with agents that run the tests and pins on a git-archive export; (2) hand the review notes to navigator-research agents scoped per repo, asking for verified path:line refs and a recommended issue split; (3) write bodies with Context/Implementation/Acceptance H2, paste-output + mutation-pin bullets, no-decompose label; (4) chain same-file issues with 'Blocked by: #N'; (5) pre-flight every backticked path; (6) review again.
