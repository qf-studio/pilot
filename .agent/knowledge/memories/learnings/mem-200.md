# Learning: Verifying a tenant secret rotation: the config file never changes; check the unit's env file mtime, the daemon restart, and the token-validated log line

## Summary
On a fleet tenant the daemon config references secrets by env var (token: "${GITHUB_TOKEN}"), and the systemd unit loads EnvironmentFile /run/pilot/env, which /opt/pilot/fetch-secrets.sh rewrites from SSM at every unit start. So after a Connections PUT (token re-save) the proof chain is: SSM parameter Version+LastModifiedDate advanced → pilot.service Stopping/Started in journalctl within ~1 min → /run/pilot/env mtime one second after start → 'GitHub SDK poller token validated' log line. The config file mtime does NOT move and must not be read as 'push did not happen'. My IAM user cannot kms:Decrypt the tenant key (by design), so hash-compare against SSM is not available; the env-file mtime + validated line is the evidence.

## Context
2026-09-28 tenant GitHub token rotation after the founder regenerated the pilot-saas token; first read of the untouched config mtime looked like a failed push.
