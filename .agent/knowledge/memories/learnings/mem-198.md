# Learning: Console repo switch in the UI is inert on a live tenant: PATCH connections never bumps config_generation

## Summary
Only PUT connection (token rotation) and PUT credential call refreshInstanceConfig; the PATCH the UI uses for repo changes saves the row and returns 200 but the reconciler sees no drift, so the box keeps polling the old repo. Workaround: re-save the token (PUT). Fix console#323. Corollary: the hosted render omits use_worktree/sync_main_after_task, so tenants execute in the project root unlike the box (console#324).

## Context
2026-09-25: founder switched the tenant repo, tenant config file untouched 2 h later; found by reading handlers.go lines 544/872 vs the PATCH handler.

## Correction (2026-09-28, post-merge review of console PR#328)
The causal story above is wrong. The instance journal shows the repo switch DID reach the box on 09-25: `reconcile.repos_synced` gen 4 (repos=[pilot-ship-test-go]) at 10:09:21Z, `config.push_completed` gen 4 at 10:10:33Z, ten minutes after the 10:00:42Z PATCH, not two hours. The PATCH bump added by PR#328 cannot deliver a repo change at all: `BumpConfigGenerationForOrg` re-inserts the current generation's params and `ConfigPusher.Push` renders the stored YAML, so that path only re-runs fetch-secrets. `Reconciler.syncRepos` is the sole path that puts a new repo list in a generation; it reads the connection row every 60 s tick. The real unknown is why syncRepos saw no diff for ~8 ticks after the PATCH and then bumped 15 s after the token PUT (no restart, no error lines, and the reconciler writes no per-tick log in prod, console#319). Do not cite "PATCH never bumps" as the cause of a stuck repo switch; read `GET /api/v1/instances/{id}/events` first.
