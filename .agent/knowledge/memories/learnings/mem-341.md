## Summary
Correction to mem-339 (2026-11-25): run_as_user does NOT need a GitHub App to run in a private repository. The daemon fills the agent workspace from its own repository through a git bundle piped to the agent user (transportWorkspaceBase), takes the commit back, pushes and opens the pull request with its own credential; with no read token the run goes on with one Warn line (startRunAgentTokenFile). Without the App the agent only lacks gh and a fetch from GitHub inside its session, and a gate that downloads a private dependency as the agent user fails. A session repeated 'private repositories fail without the App' for two days from one line of a task document ('no gh and no fetch of a private repository') without a read of the code, and the founder kept the option off on that claim. Before a report names a blocker, read the code path that would fail.
