# Learning: Ready for review means merge on the stage environment; a security PR stays in draft until the founder writes merge

## Summary
On the stage environment the Pilot daemon merges a PR by itself as soon as the PR is ready for review and CI is green (auto_merge true, no approval request). Verified 2026-11-16 in the box log for PR 6397: marked ready 15:12:40Z, merged by the auto-merger 15:14:58Z. GitHub shows the founder account for every action, because the daemon and the planning session use one token, so the timeline cannot show who merged. For a security PR the draft state is the only hold: post the run-it verdict, keep the PR in draft, and mark it ready only after the founder writes merge for that PR. Never report that the merge is the founder's when the PR is ready.

## Update 2026-11-16 evening (founder call, replaces the "wait for merge" part)

The founder does not want a question for each PR and does not want review verdict terms in reports ("no idea on Go or Go with notes, make it done as we have a plan"). Standing instruction for the agreed plan of TASK-651: when the review finds no blocker and CI is green, mark the PR ready (the daemon merges it), then file the next ticket of the plan. Ask the founder only when the review finds a blocker, when work leaves the plan, or for a step on the box. Report in plain words: what merged, what it does, what is next. The draft hold stays in place until the review is done.

## Recommended Approach
