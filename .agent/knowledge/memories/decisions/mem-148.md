# Decision: Dashboard nav rework: port grom grid/focus code into pilot, don't promote to grot pkg

## Summary
TASK-398 (#4199): grom's spatial focusMove/Rect/zoom machinery lives in grot internal/app — not importable. Port ~200 lines into internal/dashboard/grid.go with attribution instead of promoting to grot pkg/tui + release + dep bump.

## Context
Planning the grom-style panel navigation rework (spatial hjkl focus, enter-zoom, fluid layout) for pilot's dashboard, 2026-07-11.

## Details
Reusable core is tiny and pure (focusMove/overlaps/cropVertical ~100 lines); the rest of grom's grid (autoFlow, gridPosLayout, typeHeight) is coupled to Grafana WidgetSpec and wrong for pilot's bespoke two-column layout. grot v0.1.0 pkg/tui/widget.Widget interface is Prometheus-shaped (SetResult(QueryResult)) — pilot uses a thin panelDef registry over existing Model render methods instead. Promote to grot pkg only if a third consumer appears. Ported source embedded verbatim in the TASK-398 spec because Pilot executor worktrees cannot reach ../startups/grot.

## Recommended Approach
When pilot needs grot-repo internals: embed the ported source in the issue spec (executor can't read sibling repos); prefer port-with-attribution over cross-repo API promotion until >=3 consumers.
