## Summary
Pilot as cross-repo hub: every wired project (config projects:) takes work as pilot-labeled GitHub issues — humans and machines both request changes by filing issues on the target repo; Pilot executes, gates filter (spec-guard, blocked-by, intent judge, CI-fix size guard), autopilot merges and releases. Cross-repo dependency ordering: blocked-by refs are same-repo only, so file the downstream issue UNLABELED and add the pilot label once the upstream release exists (label-as-trigger). Proven: studio-sdk#79 (auto-tagged on pilot-branch merge) -> pilot#3921 (consumer bump, label-gated). Gap: no automated release->consumer-bump propagation.
