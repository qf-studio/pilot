# Pattern: Atomic-claim idiom: INSERT OR IGNORE + RowsAffected==1 on a composite-PK table — the only race-safe dedup in this codebase

## Summary
ClaimSpawnedFix (state_store.go:1062, #4319) is the proven template: composite PRIMARY KEY table, INSERT OR IGNORE, winner = RowsAffected()==1. SQLite serializes it across goroutines AND processes. Generalized to execution dispatch in TASK-407/#4349 (execution_claims with a generation column so legitimate retries claim generation+1 instead of deadlocking).

## Context
Distilled 2026-07-16 from the duplicate-execution class RCA. Contrast: every failed guard was SELECT-then-INSERT in separate transactions (TOCTOU), or in-memory per-process state, or a decaying lease.

## Details
Recipe: (1) dedicated claim table, composite PK = the invariant key, canonicalize any path-like key component once; (2) claim BEFORE side effects, typed error on loss; (3) permanent rows + generation column for retries (immune to crash windows vs delete-on-terminal); (4) inventory test: two concurrent claims -> exactly one winner under -race.

## Recommended Approach
Reach for this pattern whenever the sentence 'X must happen at most once per K' appears. Do not reach for mutexes (process-scoped) or leases (decay).
