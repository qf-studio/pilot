# Pitfall: Merged is not live on the hosted console: UI deploy is dispatch-only and the console tag is never cut, so autopilot-merged PRs sit undeployed

## Summary
console.pilotcloud.dev served the 09-24 build (stamp 961bd42) on 09-28 while main was at 35436d6 with three merged UI PRs; the founder saw the old avatar menu and read it as 'still not fixed'. Cause: pilot-console-ui deploys only on workflow_dispatch or a prod-* tag; pilot-console deploys only from a prod-X.Y.Z tag that nothing cuts (prod-0.1.0 from 09-08 is the only tag, so PR#328 is merged but not in prod). Autopilot merges on green CI, so every merge silently stops at main.

## Context
2026-09-28, founder asked why the Settings entry discussed on 09-25 was still missing. Fixed same hour by a manual UI dispatch (live stamp = merge commit). Automation filed: ui#178 (deploy on green CI on main), console#331 (auto-cut next prod-X.Y.Z tag on green CI on main; includes the fix for the deploy passing TenantFactory=false on Release-triggered runs, which would switch provisioning off).

## Recommended Approach
Before declaring a console/UI change 'shipped', compare the live stamp with main: curl console.pilotcloud.dev/build-sha.txt vs gh api repos/qf-studio/pilot-console-ui/commits/main; for the API, compare the console-api task definition image tag with the newest prod-* tag. Until #178/#331 land: dispatch the UI deploy after each UI merge batch and cut a prod-X.Y.Z tag after each console merge batch.
