# Pitfall: Backticked nonexistent repo-path-like spans in a pilot issue body trigger an indefinite referenced-path prerequisite hold

## Summary
The dispatcher's referenced-path prerequisite gate extracts backticked path-like spans from a `pilot`-labeled issue body and holds the task ("Task held: prerequisite not on main", re-checked every ~5min poll, forever) if any span is missing from the default branch. Fabricated/fixture/hypothetical paths written in backticks look identical to real prerequisites. GH-5221 incident (2026-08-25): a deliberately fake test-fixture path (a `navigator/9.0.0/...` plugin-cache template) in the Implementation section held the task for 12+ cycles. Recovery: reword the body so the fake path is prose, not a backtick span — the hold clears automatically on the next poll after `gh issue edit`; no relabel/close needed.

## Context
Follow-up issue #5221 (auto-init ensure-sections invariant) was authored with a backticked fabricated path describing a test fixture to be created. The dispatcher treated it as a prerequisite file. Diagnosed from box `daemon.log` (`reason="referenced path ... not found on default branch"`); nothing is posted on the GitHub issue itself — the hold is invisible without daemon logs or the notification channel.

## Details
- The gate reads backtick spans that look like repo paths and stats them against the default branch (same family as the dependency gate; see also mem-175's variant where held paths were cached on the execution row and close+refile was required — in the GH-5221 case a plain body edit was sufficient and the task dispatched on the next tick).
- Hold is level-triggered and infinite: `hold_count` climbs every poll; the task never fails, never surfaces on the issue.
- This is distinct from Rule 3 (dependency refs): that gate *silently ignores* malformed input; this gate *blocks* on well-formed-looking input.

## Recommended Approach
Backtick only paths that exist on main. Describe hypothetical, fixture, or to-be-created paths in prose ("a fabricated plugin cache dir for a fake version 9.0.0"). Codified as SOP Rule 3b in `.agent/sops/onboarding/new-project-issue-authoring.md`. If a task is already held: `gh issue edit` the body, then wait one poll cycle; verify dispatch in `daemon.log`.
