# Pitfall: gitlab.com Free tier refuses group AND project access tokens via API; only a personal access token works for a daemon

## Summary
On a gitlab.com Free-plan group, POST /groups/:id/access_tokens and POST /projects/:id/access_tokens both return 400 'User does not have permission to create … access token' even for a group Owner. The glab CLI login is an OAuth session token (personal_access_tokens/self rejects it) and cannot be reused on a server. Only a user-created PAT (scopes api + write_repository) works; it must come from the founder (UI), and it doubles as the git credential (credential.helper store, https://oauth2:<pat>@gitlab.com).
