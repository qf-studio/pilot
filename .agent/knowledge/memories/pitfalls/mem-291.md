# Pitfall: SSM RunShellScript payloads lose shell variables inside sudo -iu … bash -c; a for-loop over task ids ran pilot task cancel with no argument

## Summary
Second occurrence (2026-11-05 17:0xZ; first 2026-11-05 15:xxZ with a grep path): a payload 'sudo -iu ec2-user bash -c "for t in GH-6107 GH-6108; do pilot task cancel $t …; done"' reached the box with $t empty and printed 'accepts 1 arg(s), received 0' twice. The JSON/quoting layers of send-command strip the dollar expansion before bash runs. Write literal ids and literal paths in SSM payloads; one command per id.
