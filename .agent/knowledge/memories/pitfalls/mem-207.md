# Pitfall: A remote mutation script shipped over SSM ran with an EMPTY secret and archived a live clone before its re-clone failed

## Summary
The token mint failed on zsh globbing ('scopes[]=api' expanded), the variable stayed empty, and the box script — already sent — moved linearinvoices-service to a .gh-archive dir, failed the authenticated clone, and set -e aborted mid-loop. Restored from the archive 8 minutes later; an empty 'export GITLAB_TOKEN=' line and an empty git credential entry also had to be cleaned.

## Recommended Approach
Any script that mutates the box with a secret: assert the secret is non-empty locally BEFORE building the SSM payload ([ -n "$TOK" ] || exit 1), make the script idempotent (archive only when the live dir still points at the old remote; clone only when the dir is absent), and put the destructive step (mv) AFTER the step that proves the credential (ls-remote/dry-run push).
