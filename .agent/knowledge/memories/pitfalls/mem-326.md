# Pitfall: A quality gate that reports 'make test-changed exited with code -1' was killed b

## Summary
A quality gate that reports 'make test-changed exited with code -1' was killed by its time limit; no test failed (the output tail shows only ok lines). On the founder box (4 CPUs) the test gate has a limit of 10 minutes and runs almost the full Go suite for a change in internal/executor; under the load of orphan processes the suite needed about 10 minutes there (it needs 3.5 minutes on the quiet box: the gate of issue 6514 passed in 3m31s right after the stop of the orphan processes on 2026-11-19; the limit is 20 minutes since that day), so a ticket passed only on a lucky run (issue 6500: third gate run; issues 6501 and 6503: three failed runs each on 2026-11-18 and 11-19, one ticket parked). The box also held 133 orphan process trees of old agent sessions (wait loops of background tasks that poll with pgrep or sleep, and vite dev servers of removed worktrees, up to 54 days old): 271 processes, load average 17 to 21. An agent run does not stop its background shells and dev servers at its end. Before a retry of a ticket with exit -1: read the gate duration in the daemon log (about 2 x the limit means a time limit), then the load of the box (uptime, ps by ppid 1 and age). The orphan load was the main cause; the stop of the orphan trees fixed the gate before the new limit was active.
