# Pitfall: Plane has two copies of its code and production uses the SDK one: polling intake

## Summary
Plane has two copies of its code and production uses the SDK one: polling intake, state changes and comments run through studio-sdk (cmd/pilot/poller_plane.go), while internal/adapters/plane is live only for the config type and the webhook handler (its Client, Poller and Notifier have no production caller). On 2026-11-25 an outside pull request (6510) that made the internal Priority type accept text values was merged on the founder's approval BEFORE the code research ran; the research then showed the fix was in the copy that no poller decodes into, and the SDK at v0.38.7 still has 'type Priority int' with no decoder, so a Plane server that sends priority as text (the documented API form: none, urgent, high, medium, low) makes each page of work items fail to decode and Pilot takes no ticket, with a Warn each poll. Rule: for an adapter fix, find the production caller of the changed type before a merge; research first, merge second.
