# Pitfall: ProjectWorker is the sole per-repo serialization point; orchestrator.max_concurrent is neutralized

## Summary
All issue dispatch (in-tree + SDK pollers, all execution modes) funnels into Dispatcher.QueueTask keyed by task.ProjectPath; ProjectWorker.processQueue (internal/executor/dispatcher.go:843-899) holds a processing.CompareAndSwap guard and executes runner.Execute synchronously one task at a time. orchestrator.max_concurrent (config.go:149, default 2) only governs poller goroutines that then park in WaitForExecution polling the same worker — it has no practical effect on single-repo throughput.

## Context
TASK-393 research (2026-07-09), 3-agent navigator-research sweep.
