# Pitfall: The untracked pilot-console compose override points the local console at production SSM; a local platform-key assign would double-lend a real pool key

## Summary
`pilot-console/docker-compose.override.yml` (untracked, added 2026-08-19 for the docs-page E2E) sets `PILOT_CONSOLE_SECRETS_DRIVER=ssm` with the founder's `quantflow` AWS profile mounted. Compose loads it automatically, so `make local-up` runs the local console against the production parameter store. With the platform key pool on, a local `consolectl platform-key assign` (or a local provision) would read the REAL pool values from `/pilot-fleet/console/platform-keys`, claim a row only in the LOCAL `platform_keys` table, and write the real key into prod SSM under `/tenants/<local-org-id>/ANTHROPIC_API_KEY` — while the prod table still lists that key as free, so a later prod assign hands the same key to a real tenant.

## Context
2026-10-06 TASK-511 real-stack verify on the local stack, right after TASK-502 leg 1 went live (pool free 5). Caught while reading the override before `make local-up`.

## Details
The override exists for two local features: UI credential saves landing where the box's apply script reads them, and the instance proxy reading `PILOT_GATEWAY_TOKEN`. Both need the SSM driver. The pool reader and the tenant secrets writer pick their backend from the same driver switch (`secrets.NewWriterForDriver` / `platformkeys.NewReaderForDriver`), so the SSM posture leaks into pool operations too. Nothing in consolectl or the console distinguishes "local stack" from "prod" once the driver is ssm and the credentials resolve.

## Recommended Approach
For pool / allowance / billing work on the local stack run `COMPOSE_FILE=docker-compose.yml make local-up` (ignores the override; postgres driver, no AWS). Seed fake pool values in `local_secrets` with `org_id = '/pilot-fleet/console/platform-keys'` and matching `platform_keys` rows (`status='free'`); `platform-key sync` is not usable locally (it needs the real Admin API), `assign`, `status` and `billing set-allowance` are. Run the console natively with `ANTHROPIC_ADMIN_API_KEY=<any non-empty value>` to wire the pool view; the request path never calls the Admin API. Never run `platform-key assign` or provision against a console whose secrets driver is ssm unless the DATABASE_URL is the production database too.
