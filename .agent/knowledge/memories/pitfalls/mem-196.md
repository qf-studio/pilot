# Pitfall: Flag-gated worker verified locally, never enabled in the prod task definition — board empty by construction

## Summary
pilot-console's board sync workers (SYNC_INGEST/SYNC_OUTBOUND/APPROVAL_INGEST) default off; the S4 exit ran with them on locally, but the pilot-fleet console-api task def never set them, so the live Board/Needs You were empty with zero errors. Same class as the mock-UI false success: a feature gate that only exists as an env var is not shipped until the prod task def carries it.

## Context
2026-09-25, first fleet tenant shipped end to end and the board showed nothing; console-api logs had no ingest lines at all.

## Details
Diagnosis path: describe-task-definition on the live family, diff PILOT_CONSOLE_* names the binary reads (grep os.Getenv) against names set; every worker gated by 'if cfg.X.Enabled && DatabaseURL' in main.go that is absent from the task def is silently off. Deploy chain is CI but manual: infra Deploy Pilot Fleet 'all' (only choice that hits the S3 template sync) then console Deploy QuantFlow AWS with image_tag + tenant_factory=true (default false would switch the factory off). Anyone with repo rights can dispatch; it is not Nelya-only.

## Recommended Approach
For every env-gated feature: add the prod task-def value to the acceptance criteria of the leg that ships the gate, and after each service deploy diff the live task def env against the binary's Getenv list. Ground truth for the console: /metrics via the ALB directly (CloudFront serves the SPA for /metrics) with Host + bearer /pilot-fleet/console/API_TOKEN + X-Origin-Verify.
