# Pitfall: The stale-label cleaner builds its active set from running executions only (inte

## Summary
The stale-label cleaner builds its active set from running executions only (internal/adapters/github/cleanup.go ~271-283 via store.GetActiveExecutions = status='running'), so a queued-but-waiting task loses pilot-in-progress once the issue is idle past adapters.github.stale_label_cleanup.threshold (default 1h). The poller then re-offers it while its queued row still owns the claim. Seen 2026-11-06 on pilot#6152 during a self-upgrade admission pause (queued 15:12Z, stripped 16:27Z). Fix: TASK-641 D2 — count queued/pending rows as active.
