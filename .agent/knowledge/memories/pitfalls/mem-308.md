# Pitfall: The push secret gate decides what is already published from refs inside the repo

## Summary
The push secret gate decides what is already published from refs inside the repository the agent session can write. Review of PR #6323 (2026-11-12) confirmed seven shapes that publish a registered value on main: a forged remote-tracking ref (update-ref refs/remotes/origin/main HEAD), a session-added remote that points at a local bare repo, a replace ref or graft that hides the commit, and (in that PR) a forged reflog entry. Never widen the gate's trust in local refs, reflogs or the shallow file to remove a false refusal. The fix is structural: scan and push from a repository the agent cannot write (TASK-651 U2) and run the gate's git calls with GIT_NO_REPLACE_OBJECTS=1.
