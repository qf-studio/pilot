# Pitfall: Dead-code audit: verify caller LIVENESS, not just existence (SOP GH-4169 misclassified poller.go)

## Summary
The GH-4169 dead-code SOP listed internal/adapters/github/poller.go as 'live' because callers existed — but every caller was a test file. Auditing symbol existence alone keeps genuinely-dead code. Audit whether callers are PRODUCTION or test-only.

## Context
TASK-397 W1: origin/main grep showed github.NewPoller + all 8 With* options had zero NON-test references; only tethers were gh3819_cross_project_test.go + stress/{concurrent,memory}_test.go. project_board.go had zero callers at all. Both had slipped past the GH-4169 cleanup, which reviewed an 8-file list by existence.

## Details
The live poller is the SDK one (sdkGithub.New(cfg).NewPoller, poller_github.go:407). In-tree poller.go + project_board.go were superseded. Same trap could hide any file whose only remaining callers are tests.

## Recommended Approach
When deciding a file is dead: grep callers, then classify each as production vs test. A file reachable only from *_test.go is deletable (retire/rehome the tests). Contrast with the 4d.6 lesson (over-listing dead files) — both failure modes come from not checking caller liveness precisely.
