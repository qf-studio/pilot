# Pitfall: A secret in a URL path leaks through *url.Error; a same-uid agent reads every daemon secret

## Summary
Telegram puts the bot token in the URL path; every network error wrapped a *url.Error whose text holds the URL, so 134 daemon.log lines kept the token for 30 days. Separately, agent sessions run as the daemon's uid: on 2026-08-03 a diagnosis ticket (GH-4669) led an agent to run `cat ~/.pilot/config.yaml | head -60` on the box, and the recording kept the output.

## Context
2026-11-09: found in the box log after the v2.316.0 upgrade (preflight error line). Research then found the 2026-08-03 recording TG-1785766274768 with the full config. CI's secret scan covers tracked files only and had no Telegram pattern; no runtime redaction existed.

## Details
Go's *url.Error.Error() prints Op, the full URL and the cause. Any credential in the path or query string reaches every %w wrap, log line and alert. Header credentials do not leak this way, but body echoes and %v of a request still can. Pattern-based redaction misses secrets with unknown shapes (Anthropic keys with hyphens, Jira, Discord). An env-name denylist does not hide secrets from a same-uid process: it can read the config file and /proc/<daemon>/environ.

## Recommended Approach
0) Never ask an executor ticket to diagnose the live box (metrics, logs, config): an agent on the box takes it as licence to read daemon state. Box diagnosis runs in a Navigator session over SSM.
1) Send credentials in headers; when an API forces the URL (Telegram), route every request through one helper that rewrites *url.Error.URL before any wrap (PR#6245). 2) Register configured secret values at startup and redact by exact value in every sink: logs, alerts, recordings, DB (TASK-650 L1). 3) Scan sinks for leaks and alert (L2). 4) Canary leak test per adapter, enforced in CI (L3). 5) Treat same-uid agent access as full access: read guard as a stopgap (L4a), separate uid as the fix (L4b). 6) After a leak: rotate, then mask the sinks in place (same inode for a live log).
7) Route GitHub secret-scanning alerts to a person (TASK-650 L6). On 2026-04-07 GitHub flagged a real Telegram token that a Pilot executor committed to a doc; the alert stayed open for 7 months. A history rewrite does not remove a pushed commit: GitHub serves it by SHA and forks keep it. Rotate first.
