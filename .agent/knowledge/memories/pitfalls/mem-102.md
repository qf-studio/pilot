# Pitfall: CreateWorktreeWithBranch builds a fresh WorktreeManager per call — concurrent same-repo execution reintroduces the GH-1312 git race

## Summary
WorktreeManager.createMu exists solely to serialize 'git worktree add' (GH-1312 race on .git/worktrees/*/commondir). The pooled path shares one manager (r.worktreeManager), but the non-pooled helper CreateWorktreeWithBranch (internal/executor/worktree.go:768-775), used by Runner.executeWithOptions when the pool is not configured (runner.go:1767-1793), constructs a NEW manager — and a new, unshared mutex — on every call. Serial execution masks this today; N-concurrent execution per repo would silently lose the race protection.

## Context
TASK-393 research (2026-07-09). Declared the hard prerequisite (P3.1) before the ProjectWorker pool ships.

## Recommended Approach
Before any per-repo concurrency: route ALL worktree creation through one shared WorktreeManager per project. Also re-verify worktree path allowlist resolution via git rev-parse --git-common-dir (mem-083) since concurrent worktrees multiply exposure.
