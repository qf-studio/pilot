# Pitfall: A per-tick deadline context leaks into goroutines the tick spawns — the comment said "long actions keep running against the parent ctx", the code passed tickCtx, and prod provisioning was dead for 13 days

## Summary
Console PR#321 (2026-09-24) wrapped the reconciler tick in `context.WithTimeout` + `defer cancel()`. Every goroutine the tick dispatched (`dispatchLong` → provision/terminate/recover, `dispatchConfigPush` → SSM push) received that `tickCtx` and died ~1 s later when the tick body returned. The `TickTimeout` doc comment explicitly promised the opposite. No test pinned it, no prod provision ran between the deploy and 2026-10-07, so the fleet could not provision a box for 13 days and nobody saw it.

## Context
TASK-513 (2026-10-07): first real provision after PR#321 looped once per minute (`context canceled` at every stage; `fail()` settled on the same canceled ctx so the row never flipped). Fixed in two legs: console#367→PR#368 (provision), console#369→PR#370 (config push). Nelya found the loop independently in the reconciler log.

## Details
Symptoms in the log: an action starts right after `reconcile: tick … duration_ms≈1000`, then `… canceled, context canceled` 1–5 s later, and the failure handler's own store writes fail with the same error. `platform_keys_free` drops by one and stays. Crash recovery (StuckAfter 15 m) reaps the row to `error`. The 400 `Invalid IAM Instance Profile ARN` seen once in the loop is ordinary IAM propagation lag — not a separate defect.

## Recommended Approach
- Any goroutine spawned from a deadline-bounded body must take the long-lived run context (`r.runCtx`), never the bounded one. Grep `go func` in the reconciler after any ctx change; PR#370's audit lists the sites.
- Failure/settle paths must run on `context.WithoutCancel(ctx)` + a short timeout, because the cause of the failure is often the cancellation itself.
- A doc comment that describes concurrency behaviour needs a test that would fail if the comment were wrong (`TestReconcilerLongActionOutlivesDispatchingTick`, `TestReconcilerConfigPushOutlivesDispatchingTick`).
- After any reconciler change, provision one real box on prod before calling it done; unit tests on fakes did not catch this.
