# Pitfall: Duplicate-execution class: leases and check-then-act guards are not claims — 10 incidents, 7 entry points, 6 keys

## Summary
Dispatch has two independent channels (poller->dispatcher vs epic direct-exec at epic.go:2008 which NEVER consults IsTaskQueued). Every dedup guard is a separate-transaction check-then-act with its own key (PR#, bare task_id, (task,project), 5-min poller lease, in-memory per-process marks) — so each point fix was correct for its incident and irrelevant to the next. Sandbox GH-82 ran 6x on a daemon with ALL prior fixes live — per PR #4350's finer ledger read: a SEQUENTIAL poll-interval no_op re-pick loop (no_op outcomes invisible to HasCompletedExecution), fixed as the 11th point patch. The two-channel concurrency gap remains code-verified and open until the claim lands.

## Context
2026-07-16 founder escalation ('again and again re-executions, complete mess') after canary duplicate-pr assert x3. Two-track research: nav-research gap matrix (7 entry points x 9 guards) + 10-incident history Jul04-15 (~185 excess executions, ~$115; fix tasks themselves ran 5x/4x/4x). Poller mark decays after retryGracePeriod (~5min) while epic children queue 10-40min; marks are per-process in-memory, wiped by restart; reconcileChildOutcome only reconciles on FAILURE — successful concurrent dupes invisible; executions table has NO uniqueness constraint.

## Details
Never fix this class by adding another check or lengthening a lease. The only durable form is an atomic durable claim at the single seam all entry points share (ExecutionLifecycle.Begin). Systemic fix: TASK-407 / pilot#4349 (execution_claims (task_id, project_path, generation) PK, INSERT OR IGNORE + RowsAffected==1, ErrClaimLost at every call site). #4347 is a consumer. Verification gate: scheduled epic-lifecycle canary green on duplicate-pr, then #4265 closes.

## Recommended Approach
Any new dispatch path MUST route through ExecutionLifecycle.Begin and handle ErrClaimLost. Any future duplicate incident: check the claim table first, not the guards. If a guard is added anywhere, ask why the claim did not cover it.
