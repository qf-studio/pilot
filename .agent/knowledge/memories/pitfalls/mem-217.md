# Pitfall: Cancelling a console deploy run mid-job does not stop CloudFormation; the next dispatch fails on UPDATE_IN_PROGRESS and the cancelled image still lands

## Summary
`gh run cancel` on `deploy-quantflow-aws.yml` stops the GitHub job, not the CloudFormation stack update the job already started. The cancelled run's image keeps rolling out (console-api went to prod-0.1.14), and a dispatch issued right after fails in the api job with "Stack … is in UPDATE_IN_PROGRESS state and can not be updated", skipping reconciler and workers.

## Context
2026-10-07 TASK-512: I dispatched `image_tag=prod-0.1.14` without reading the newest tag; prod-0.1.15 (PR#366) had auto-cut and auto-deployed 15 min earlier. Cancelled after the mirror job; the api job had already called CreateChangeSet. Re-dispatch 37590661945 failed; the three stacks reached UPDATE_COMPLETE ~2 min later and a third dispatch went through.

## Details
The deploy workflow renders each service's task definition from the S3 template and updates one CloudFormation stack per service (`pilot-fleet-svc-console-{api,reconciler,workers}`) in sequence, with `--no-fail-on-empty-changeset`. A changeset in flight is owned by CloudFormation, so a cancelled job leaves the stack updating with the cancelled run's parameters. There is no rollback of the cancelled run.

## Recommended Approach
Before any manual dispatch: `git fetch --tags && git tag -l 'prod-*' --sort=-creatordate | head -1` and `gh run list --workflow deploy-quantflow-aws.yml --limit 1` — the auto-deploy on main may already have moved past the tag you have in mind. If a wrong dispatch is already running, let it finish and dispatch the right tag afterwards; do not cancel. If it was cancelled: `aws cloudformation describe-stacks --stack-name pilot-fleet-svc-console-api --query 'Stacks[0].StackStatus'` must read UPDATE_COMPLETE (or ROLLBACK_COMPLETE) before the next dispatch. Verify the outcome on the service, not the run: `aws ecs describe-services --cluster pilot-fleet --services console-api console-reconciler console-workers` → task definition → image tag and env.
