# Pitfall: Base-presence hold caches referenced paths on the execution row at CREATION — ed

## Summary
Base-presence hold caches referenced paths on the execution row at CREATION — editing a wedged issue's body does NOT clear the hold. On 2026-08-23 #5145 wedged because its body had backtick-quoted example paths (q-<epoch>.md, q-1786987124.md) the base-presence guard (internal/executor/base_presence.go) extracted and probed on main; not found -> permanent 'prerequisite not on main' hold, hold_count climbed, escalated pilot-needs-human, execution marked skipped/terminal, poller then 'Skipping re-dispatch — completed execution exists'. Rewriting the body + label-cycle did NOT help: dispatcher kept holding the SAME execution_id citing the OLD cached path. Recovery that works: CLOSE the issue and REFILE fresh (new issue = new execution, reads the corrected body) — verified, #5147 dispatched clean. IMPORTANT: v2.267 glob-exclusion only spares wildcard paths (q-*.md); a literal/placeholder backtick path with no wildcard (q-<epoch>.md) still wedges. Never put backtick-quoted non-existent example paths in an issue body.
