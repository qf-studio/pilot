# Pitfall: Base-presence hold caches referenced paths on the execution row at CREATION — ed

## Summary
Base-presence hold caches referenced paths on the execution row at CREATION — editing a wedged issue's body does NOT clear the hold. On 2026-08-23 #5145 wedged because its body had backtick-quoted example paths (q-<epoch>.md, q-1786987124.md) the base-presence guard (internal/executor/base_presence.go) extracted and probed on main; not found -> permanent 'prerequisite not on main' hold, hold_count climbed, escalated pilot-needs-human, execution marked skipped/terminal, poller then 'Skipping re-dispatch — completed execution exists'. Rewriting the body + label-cycle did NOT help: dispatcher kept holding the SAME execution_id citing the OLD cached path. Recovery that works: CLOSE the issue and REFILE fresh (new issue = new execution, reads the corrected body) — verified, #5147 dispatched clean. IMPORTANT: v2.267 glob-exclusion only spares wildcard paths (q-*.md); a literal/placeholder backtick path with no wildcard (q-<epoch>.md) still wedges. Never put backtick-quoted non-existent example paths in an issue body.

## Update 2026-09-22 (box v2.276.1) — body edit DOES clear the hold now; new token class

- pilot-console-ui#164 was held 3× (13:04–13:11Z, every 5 min) on `referenced path "SITE=https://console.pilotcloud.dev" not found on default branch`. The offending text was an inline-code **env assignment**, `SITE=https://console.pilotcloud.dev` — the extractor takes any backticked token with a dot-suffix (`.dev`, `.ref` in `inputs.ref`, build-output paths like `dist/index.html` that are not in git) as a repository path.
- **The hold is no longer permanent on v2.276.1.** ui#164: holds 13:04/13:06/13:11Z, body edited ~13:13Z, `Starting task execution` 13:16Z (same execution_id). ui#167 the same afternoon: holds 13:38/13:41Z, **started 13:46Z with NO body edit yet** (edit landed 13:52Z). So the release is the dispatcher giving up the hold after ~3 processing ticks (~8 min), not the body edit — the 08-23 close+refile recovery is unnecessary now; just wait, or edit the body if it will be re-read anyway. Cost is ~8 min of queue-head time per offending token.
- Rule for authoring (extends the 09-03 one): before `gh issue create`, un-backtick every token that has a dot-suffix and is not a path present on main — env values, URLs, hostnames, build artefacts, action refs (`oven-sh/setup-bun@v2` is fine, no dot), `inputs.ref`. Checking only the *cited repo paths* is not enough; the false positives are the non-paths.
