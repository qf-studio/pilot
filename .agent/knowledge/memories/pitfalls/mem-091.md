# Pitfall: Flag-gated path swaps orphan sideband wiring loops (SDK poller unreachable by MarkProcessed/ClearProcessed loops)

## Summary
When a flag replaces a component (use_sdk_poller swapping in-tree poller for SDK poller), every sideband loop wired to the OLD instance collection silently loses coverage: main.go's for-range-ghPollers loops (GH-3240 sub-issue skip, GH-3271 SetOnIssueDone re-mark, stale-label ClearProcessed) never reach the SDK poller — its handle never leaves the CreateAndStart closure and it lacked exported MarkProcessed. Confirmed live: epic GH-3927 children 3952/3953/3954 double-dispatched 07-07; GH-3954 ran twice concurrently. Second incident of the family after mem-089 (field drops).

## Recommended Approach
Audit checklist for any A/B component swap: (1) grep for-range over the old collection type; (2) for each sideband callback (skip/mark/clear/notify), assert the new instance is registered in the same collection or an equivalent registry; (3) exported-surface parity check on the replacement type.
