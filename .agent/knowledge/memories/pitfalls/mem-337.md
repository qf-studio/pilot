# Pitfall: A test window on the box needs its own clock, not only a watcher for the ticket:

## Summary
A test window on the box needs its own clock, not only a watcher for the ticket: on 2026-11-24 a session set run_as_user for a planned 30 minutes and waited for 'issue closed or parked'; the test gate failed, the daemon retried the ticket six times (about 44 minutes each), and the option stayed on for 4 hours 49 minutes until the ticket was parked. For each temporary state of the box (an option on, a label removed, a config test) start a second watcher with a hard time limit that reports when the limit passes, and look at the first gate result of the first attempt (about 15 minutes) before the wait goes on. A failed quality gate with should_retry is the signal to stop the window, since the retry cannot pass an environment fault.
