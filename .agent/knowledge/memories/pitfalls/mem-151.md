# Pitfall: Epic collapse to one sub-issue → scaffold-only under-delivery that passes CI green

## Summary
TASK-398/#4199: a multi-phase epic auto-decomposed to a SINGLE sub-issue with inherited-spec; the executor scoped itself to scaffolding and deferred wiring to 'a subsequent subtask' that the collapse never created. PR merged green with 3 new helper files + tests but tui.go untouched — helpers correct+tested yet entirely uncalled. Zero requirements shipped; parent auto-closed (false completion).

## Context
Diagnosing why #4199 'succeeded' (pilot-done, epic closed) yet delivered no working feature, 2026-07-11.

## Details
Two compounding failures: (1) epic decomposition collapsed 4 planned phases into one sub-issue #4200 (inherited-spec:true); the executor's own doc comments said 'wiring lands in a subsequent subtask' — but single-issue collapse means no sibling exists, so wiring is silently dropped. (2) The scaffold diff was +840/-0 across only NEW files (grid.go/panels.go/zoomlist.go); new-file unit tests are trivially green so CI/lint pass while the integration (tui.go Update/View) is missing — no test asserted j/k/enter actually change Model state. Detection: check per-file diff stat — a 'rework' PR with 0 deletions and no edits to the core file it claims to rework is a red flag. Fix: re-dispatch wiring single-scope with Update/View-level integration-test ACs that FAIL when unwired (TASK-399/#4203); merge the scaffold as foundation rather than discard it.

## Recommended Approach
For rework/refactor specs: require an acceptance test that exercises the integration seam (not just new helpers in isolation), and treat a +N/-0 diff that never edits the target file as under-delivery. When an epic collapses to one sub-issue, verify the single issue's spec still covers the whole thing — a 'wire later' deferral in a collapsed epic strands the deferred half.
