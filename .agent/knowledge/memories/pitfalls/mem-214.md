# Pitfall: Evidence gate: a 'paste the output' bullet treats every backticked span as a command

## Summary
The acceptance-evidence phrase branch (pasteOutputPatternRe) sets item.Commands to ALL inline code spans of the bullet; runPasteOutputItem returns the first allowlist failure for the whole item, so a bullet that backticks an identifier (warning, pool-03, a type name) next to a valid bun/go/make command is reported 'command not in allowlist' and the command never runs. GH-5514 fixed this only for the 'cmd passes' shape.

## Context
2026-10-05, console-ui PR#200/#201/#202 (TASK-511): all nine bun run test bullets fell to Not-verified although bun is in the default allowlist; daemon log showed regex_kind=paste_output jev_choice=paste_output agreed, so classification was right and extraction wrong.

Until pilot#5617 ships: a paste-output acceptance bullet may contain no inline code span other than the command(s); write other identifiers in plain text or quotes (SOP new-project-issue-authoring Rule 5b). Fix: use extractAllowlistedCommandSpans in the phrase branch too, falling back to all spans only when none is allowlisted.
