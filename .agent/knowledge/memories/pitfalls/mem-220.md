# Pitfall: Pilot PR bodies mark mutation-pin acceptance items 'Not verified' — the reviewer must run them

## Summary
The acceptance-evidence gate runs paste-output bullets but never runs mutation pins ('<change> -> <Test> fails'); every PR in the 2026-10-08 follow-up wave listed its pin under 'Not verified'. Post-merge review must execute the pin on a git-archive export of origin/main and state the result.

## Context
2026-10-08 follow-up wave: ui PR#214/#215/#216 and console PR#379 all shipped with the mutation pin under 'Not verified' in the Evidence block. Four reviewer agents ran each pin on a /tmp export; all four were real (e.g. removing the usePolling generation check failed exactly the new test with 'expected 2 to be 1').

**Recurrence 2026-10-08 third wave (same day):** ui PR#219 and console PR#382 shipped with an Evidence block that carried only build/test/lint output and no mutation run at all (not even a 'Not verified' line — the pin bullet lived under Implementation, so the gate never classified it). Reviewer ran both on detached worktrees: PR#219 two mutations (drop `generation++` → 3 specs fail; drop the poll guard alone → 1 spec fails with `expected [ { id: 'evt_7' } ] to deeply equal []`); PR#382 one mutation (drop `context.WithTimeout` → `err = <nil>, want *UpstreamError`). Both real. Lesson for authoring: put the mutation-pin bullet under **Acceptance**, not Implementation, so the gate at least records it.

## Details
The evidence gate (internal/executor/acceptance_evidence.go) classifies the mutation-pin shape but only records it; it does not apply the mutation and re-run the test. So a green Evidence block proves the test passes, not that it pins the change. Until the gate runs pins, the review step is the only place the pin is proven.

## Recommended Approach
In every post-merge review of a Pilot PR whose issue had a mutation-pin bullet: export origin/main with git archive to /tmp (never touch the clone), apply the described mutation, run the named test, report 'pin proven' or 'pin vacuous' with the failing assertion text. Candidate product gap: make the gate execute pins for allowlisted toolchains.
