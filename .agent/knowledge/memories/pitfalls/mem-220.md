# Pitfall: Pilot PR bodies mark mutation-pin acceptance items 'Not verified' — the reviewer must run them

## Summary
The acceptance-evidence gate only auto-runs a mutation pin when the bullet is arrow-shaped ('<change> -> <Test> fails') AND the change is the deterministic 'delete/remove line N in <file>' shape AND the repo is Go (it builds `go test` only). Freeform arrow pins are listed under 'Not verified: freeform mutation, run manually'; bullets without an arrow are classified Other and produce no line at all. Post-merge review must execute the pin on a detached worktree of origin/main and state the result.

## Context
2026-10-08 follow-up wave: ui PR#214/#215/#216 and console PR#379 all shipped with the mutation pin under 'Not verified' in the Evidence block. Four reviewer agents ran each pin on a /tmp export; all four were real (e.g. removing the usePolling generation check failed exactly the new test with 'expected 2 to be 1').

**Recurrence 2026-10-08 third wave (same day):** ui PR#219 and console PR#382 shipped with an Evidence block that carried only build/test/lint output and no mutation run at all (not even a 'Not verified' line — the Acceptance bullets had no `->` arrow, so the classifier filed them as Other and stayed silent; authoring defect, not a gate defect). Reviewer ran both on detached worktrees: PR#219 two mutations (drop `generation++` → 3 specs fail; drop the poll guard alone → 1 spec fails with `expected [ { id: 'evt_7' } ] to deeply equal []`); PR#382 one mutation (drop `context.WithTimeout` → `err = <nil>, want *UpstreamError`). Both real. Lesson for authoring: write every pin in the arrow dialect under **Acceptance** — `remove line N in <file> -> <TestName> fails` for Go repos so the gate runs it, or at least `<change> -> <test> fails` so it lands under Not verified instead of vanishing.

## Details
The evidence gate (internal/executor/acceptance_evidence.go + acceptance_evidence_run.go `runMutationItem`) applies only `parseLineMutation` edits ('delete line N in <file>'), runs `buildMutationTestCommand` (always `go test …`), reverts, and pastes the output. Any other phrasing is recorded under Not verified with 'freeform mutation, run manually' — and nothing in `prompt_builder.go` tells the executor to actually run it. Non-Go repos (console-ui, vitest) can never auto-run a pin. So a green Evidence block proves the paste-output commands pass, not that a freeform pin kills; the review step is where the pin is proven.

## Recommended Approach
In every post-merge review of a Pilot PR whose issue had a mutation-pin bullet: export origin/main with git archive to /tmp (never touch the clone), apply the described mutation, run the named test, report 'pin proven' or 'pin vacuous' with the failing assertion text. Candidate product gap: make the gate execute pins for allowlisted toolchains.
