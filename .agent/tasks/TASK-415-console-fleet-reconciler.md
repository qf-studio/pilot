# feat(fleet): reconciler — desired/observed control loop with drift sync, crash recovery, and stop/start/terminate

## Context

This is **the reconciler of workstream B (fleet reconciler & lifecycle)** for Pilot Cloud — the control loop that makes the `instances` table's desired state true in EC2. It builds on the B5 store (#11), A4 secrets writer (#12), and B6 provisioner (#22/PR#23) in THIS repo. Everything you need is embedded below — do not assume access to any other repository or design doc.

**The product being hosted**: `pilot` is a Go daemon that polls GitHub/Linear/Jira for labeled issues and executes them with Claude Code. One tenant = one EC2 instance, hard VM isolation. Root volume from a golden AMI (immutable, disposable); data volume gp3 at `/var/lib/pilot` (the tenant's state, survives instance replacement, tagged `pilot:data-volume=true`).

**Lifecycle state machine** (enforced by `internal/fleet/store.go` vocab + SQL CHECK constraints):

```
REQUESTED → PROVISIONING → BOOTSTRAPPING → RUNNING ⇄ STOPPED
                                              ├→ UPGRADING / SUSPENDED / TERMINATED
```

B6 owns `requested → … → running` (the `Provisioner.Provision` call) and its failure path. **This task owns everything around it**: the periodic loop that (a) triggers provisioning for `requested` rows, (b) syncs observed state from EC2 reality, (c) converges `running ⇄ stopped` on desired-state changes, (d) recovers rows stranded in transitional states by a crashed process, and (e) executes `desired=terminated` teardown. AMI replacement (`upgrading`), sleep/wake scheduling, and config push are later issues — see the scope fence.

**Design invariants (each has bitten this program before — encode them, don't rediscover them):**

1. **Single decision owner per state.** Every `(desired, observed, live)` combination is decided in exactly one place — a pure `decide` function — and a row with an action in flight is untouchable by the loop. (Direct lesson from a pilot-daemon P0 where a second handler drained a PR owned by another state's handler.)
2. **One state-correcting step per row per tick.** Convergence happens over ticks (observe-drift this tick, act next tick), never chained corrections in one pass — chains are where wedges hide, and single-step is what makes `decide` exhaustively table-testable.
3. **No automatic re-provision.** A `terminated` row is inert forever, even with `desired=running`. Auto-re-provision after a reap = a crashloop that costs real EC2 money. New capacity enters exclusively via a new `ClaimInstance` row (operator/API).
4. **Journal every action and every drift observation** to `instance_events` — the reconciler is the component that must never act silently.

This task must NOT be decomposed — implement as a single PR. <!-- pilot:no-decompose -->

## Acceptance

1. **Provisioner split (prerequisite refactor, this PR)**: `Provisioner.Provision(ctx, orgID)` opens with `ClaimInstance` — it can NEVER drive a row that already exists (the pre-existing `requested` row itself trips `instances_org_active_uniq` → `ErrAlreadyProvisioned`). Split it: extract everything after the claim into a new exported `ProvisionClaimed(ctx context.Context, inst Instance) (Instance, error)` (the post-claim body already keys off `inst` — the split is mechanical); `Provision(ctx, orgID)` becomes `ClaimInstance` + `ProvisionClaimed`, keeping existing behavior, tests, and the B6 e2e intact. `ProvisionClaimed` preserves the existing post-claim failure semantics (`fail()` → `provision.failed` event + observed `terminated` on that same row). Add a provisioner test pinning `ProvisionClaimed` against a pre-existing `requested` row (the reconciler's exact call pattern). Then `internal/fleet/reconciler.go` — `Reconciler` with constructor injection: `NewReconciler(store *Store, ec2c ec2API, ready ReadyChecker, prov provisionAPI, cfg ReconcilerConfig)`. `provisionAPI` is a private narrow interface (`ProvisionClaimed(ctx, Instance) (Instance, error)`) satisfied by `*Provisioner`, faked in tests; **the reconciler NEVER calls `ClaimInstance`** (invariant 3 — new capacity enters only via operator/API claims). The dispatch goroutine uses the `Instance` snapshot from the tick that decided the action. Extend the existing private `ec2API` interface with exactly `StartInstances` and `StopInstances` (update the fake; no other additions, no `CreateTags`).
2. **Tick loop**: `Run(ctx context.Context)` — single goroutine, ticks every `cfg.Interval` (default 60s), returns when ctx is done AND all in-flight actions have finished (WaitGroup). Each tick, in order:
   - **Observe**: one **paginated** tag-filtered describe per tick — drain `DescribeInstances` via `ec2.NewDescribeInstancesPaginator` (or an explicit NextToken loop; the repo's NextToken-drain precedent is `internal/secrets/writer.go`'s SSM path) with `Filters: tag:pilot:env = cfg.Env` → map `ec2InstanceID → live state`. Still never one Describe per row. **If any page errors, skip Sync entirely for this tick** (log + continue next tick) — never derive absence from a partial or failed enumeration.
   - **Sync**: applies ONLY to rows with observed ∈ {`running`, `stopped`} that are NOT in the in-flight set — invariant 1's "untouchable" covers Sync, not just decide. Rows observed `requested`/`provisioning`/`bootstrapping` are owned by their `ProvisionClaimed` call (this process, or a crashed one until `stuck` → AC 4) and are never written by Sync: in particular, live `running` does NOT promote a bootstrapping row (that is AC 4's heal path, which requires a ready probe), and absence from results does NOT terminate a provisioning row (`DescribeInstances` is eventually consistent — a just-launched id can be missing for seconds, and the tick's snapshot can predate the `EC2InstanceID` write). `upgrading`/`suspended` rows: Sync also does nothing (matches AC 3). For eligible rows: `running→running`, `stopped→stopped`, `pending`/`stopping`/`shutting-down` → leave observed unchanged (transitions settle on later ticks); live `terminated` → observed `terminated`; **absent from results → observed `terminated` only after absence on ≥2 consecutive fully-enumerated ticks** (per-row in-memory counter — debounces transient describe anomalies; a single absent tick changes nothing). On any change: `SetObservedState` + event `reconcile.drift_observed` (detail: prior observed, live EC2 state). A row that goes `terminated` via drift MUST journal the possibly-orphaned data volume: `DescribeVolumes` by `tag:pilot:org_id` + `tag:pilot:data-volume=true`, include found volume ids in the event detail (no deletion on the drift path — that evidence is for the operator).
   - **Decide + act**: for each row (deterministic order: `created_at`), compute the action via `decide` (AC 3) and execute at most one action per row (invariant 2). Long actions — provision, terminate — run in a spawned goroutine guarded by an in-flight set keyed by instance ID (rows in the set decide to `none`); at most `cfg.MaxConcurrentActions` (default 4) long actions in flight fleet-wide. Short actions (StartInstances / StopInstances / state sync / journal-only) run inline.
3. **`decide` is a pure function, exhaustively table-tested FIRST**: `decide(inst Instance, live liveState, stuck, inflight bool) action` — no I/O, no clock reads (staleness is computed by the caller and passed as `stuck`). The full matrix, every row asserted in one table test (combinations not listed here → `actionNone`):
   - `inflight` → none (always, regardless of anything else).
   - desired **running** / observed `requested` → **provision** (long).
   - desired **running** / observed `stopped`, live stopped → **start** (`StartInstances` + event `reconcile.start_issued`; observed flips to `running` via a later tick's Sync — do not set it optimistically).
   - desired **running** / observed `running`, live running → none (ready probing is AC 5, not a decide action).
   - desired **stopped** / observed `running`, live running → **stop** (`StopInstances` + event `reconcile.stop_issued`).
   - desired **stopped** / observed `requested` → none (never provision toward a stopped target).
   - desired **terminated** / observed anything except `terminated` (and not mid-transition unless `stuck`) → **terminate** (long, AC 6).
   - observed `provisioning` or `bootstrapping`, NOT `stuck` → none (owned by an in-flight `ProvisionClaimed` — possibly one from a previous process; patience until the staleness threshold).
   - observed `provisioning` or `bootstrapping`, `stuck` → **recover** (long, AC 4).
   - desired **suspended** or observed `upgrading`/`suspended` → none + WARN log once per row per process (out-of-scope states; later issues own them).
4. **Crash recovery** (the reconciler's reason to exist): a row is `stuck` when observed ∈ {`provisioning`, `bootstrapping`} and `now − UpdatedAt > cfg.StuckAfter` (default 15m — comfortably above the 5m ready timeout; in-memory in-flight guard means a live `ProvisionClaimed` in THIS process is never treated as stuck; a crashed process's orphans exceed the threshold naturally). Recovery, journaled `reconcile.recovery_started` →:
   - If `EC2InstanceID` set and live state running → probe `ready.Ready(ctx, inst)` once: green → `SetObservedState(running)` + event `reconcile.healed` (a provision that finished EC2-side but died before the final store write); not green → reap.
   - Reap (all other cases): best-effort `TerminateInstances` (if an instance exists) → volume wait-and-delete with **exactly AC 6's zero/multiple-volume semantics** → `SetObservedState(terminated)` + event `reconcile.reaped` (detail: stage, prior observed, ec2 instance id, volume ids — `[]` when none existed). The terminated row frees the partial-unique-index claim; per invariant 3 the reconciler does NOT re-claim.
5. **Ready surveillance (observe-only)**: rows with desired=running / observed=running are probed via `ready.Ready` at most once per `cfg.ReadyProbeInterval` (default 5m, per-row last-probe tracking in memory) — failure → event `ready.flapping` (detail: probe error, consecutive-failure count) + WARN log. **No automated restart/replacement in this task** — auto-recovery policy is a later issue; this task produces the evidence trail. Probe calls must not block the tick loop (probe inline is fine — SSM probe is seconds — but respect ctx deadline of `cfg.Interval/2` so a hung probe cannot starve the loop).
6. **Terminate flow** (`desired=terminated`): `TerminateInstances` (skip if no `EC2InstanceID`) → volume wait-and-delete: `DescribeVolumes` by the tag pair; **if ZERO volumes match (first lookup or any poll iteration), there is no data volume — skip the wait and `DeleteVolume` entirely**, record `volume_ids: []` in the event detail, and proceed (a `requested` row that never reached `CreateVolume` must terminate instantly, not occupy an action slot polling for 5m); if volumes match, poll until `available` (bounded 5m; timeout → journal the leaked id, still proceed) then `DeleteVolume` — **if MULTIPLE match, delete every one that reaches `available`, journaling all ids** (all are this org's data volumes; a previously-leaked volume is cleanup debt, not something to preserve) → `SetObservedState(terminated)` + events `reconcile.terminate_started` / `reconcile.terminate_completed`. Code comment required: B10 (suspend/terminate lifecycle) replaces direct `DeleteVolume` with snapshot-then-delete + 30-day retention + Stripe trigger; this is the minimal teardown that keeps the loop total and gives the e2e a clean deprovision.
7. **Config**: extend `FleetConfig` — `PILOT_CONSOLE_FLEET_RECONCILE` (`"1"` enables the loop; default off — fail-safe, console deploys without AWS wiring must stay inert), `_RECONCILE_INTERVAL` (default `60s`, validate ≥ `10s`), `_STUCK_AFTER` (default `15m`, validate > READY_TIMEOUT), `_READY_PROBE_INTERVAL` (default `5m`), `_MAX_CONCURRENT_ACTIONS` (default 4, validate ≥ 1). Defaults + validation in `Load()` with table-driven tests, mirroring the existing `loadFleetConfig` style.
8. **main.go wiring** (production entry, guarded): when `cfg.Fleet.ReconcileEnabled` AND `DATABASE_URL` set — build AWS clients (`config.LoadDefaultConfig(ctx, config.WithRegion(cfg.Fleet.Region))`, `ec2.NewFromConfig`, `ssm.NewFromConfig`), `fleet.Open` store, ready checker per `READY_MODE`, `NewProvisioner`, `NewReconciler`, then `go r.Run(ctx)`. Add graceful shutdown to main: `signal.NotifyContext(SIGINT, SIGTERM)` → `http.Server.Shutdown` + reconciler ctx cancel + wait for `Run` to return (bounded 30s; in-flight `Provision` aborted by ctx cancel takes its own failure/cleanup path, which already ignores ctx for cleanup calls). When the flag is off, main behaves exactly as today.
9. **Loop tests** (fake ec2 + fake provisioner + real store, DB-gated like existing store tests): (a) requested row → `ProvisionClaimed` dispatched exactly once across many ticks while in flight; (b) start and stop issuance incl. events; (c) drift sync: EC2 says stopped while observed running → observed corrected + `reconcile.drift_observed`, and the START happens on the NEXT tick, not the same one (asserts invariant 2); (d) EC2-side disappearance of a settled row: **one absent tick → untouched; two consecutive absent ticks → terminated + volume ids journaled** (the debounce); (e) stuck provisioning row → heal path (fake ready green) and reap path (fake ready red) both asserted incl. cleanup call ordering (fake rejects `DeleteVolume` while attached — reuse the B6 fake's discipline); (f) terminate flow happy path + **no-instance/no-volume path: desired=terminated on an observed=requested row → no `TerminateInstances`, no `DeleteVolume`, no poll-wait, row terminated with `volume_ids: []` in the event detail**; (g) MaxConcurrentActions respected (5 requested rows, cap 2 → 2 provisions in flight, rest untouched this tick); (h) shutdown: cancel ctx mid-flight → `Run` returns only after the in-flight action finishes, no goroutine leak (WaitGroup + timed assert, stdlib only); (i) **Sync ownership: a bootstrapping row with live=running, and the same row with its id absent from results, is left untouched by Sync** (no `SetObservedState`, no drift event) — both while in the in-flight set and, below `StuckAfter`, when not; (j) **pagination: fake ec2 returns the fleet across two pages → no row marked absent/terminated**; a page error → Sync skipped for the tick; (k) **ready surveillance: running/running row + fake ready erroring → `ready.flapping` event with consecutive-failure count; a second tick within `ReadyProbeInterval` (set large, e.g. 1h) issues NO second probe** — exactly one `Ready` call on the fake.
10. **E2E test** `reconciler_e2e_test.go`, env-gated exactly like the B6 e2e (`PILOT_CONSOLE_E2E=1` + `DATABASE_URL` + `PILOT_CONSOLE_FLEET_*` + KMS/secrets vars; document required vars in the test header): seed org + secrets (existing `secrets.Writer.GenerateGatewayToken`), `ClaimInstance` with desired=running (the test plays the operator/API role; the reconciler then drives the claimed row via `ProvisionClaimed` — it never claims), start the reconciler loop, assert convergence requested→running (ready green) with the full event trail; flip `SetDesiredState(stopped)` → converges stopped; flip back running → converges running; `SetDesiredState(terminated)` → instance terminated, volume deleted, row terminated. `t.Cleanup` MUST unconditionally terminate the instance, delete the volume, and `DeleteAll` secrets regardless of test outcome. Does NOT run in CI.
11. `make build`, `make test`, `make lint` green. Conventional-commit PR title.

Sequencing inside the PR: `decide` + its exhaustive table first (pure, self-contained), then observe/sync, then actions + in-flight machinery, then recovery/terminate, then config + main wiring, e2e last.

**Execution constraint: implement fully locally — make NO real AWS calls during this task.** All verification happens against fakes and the Postgres-gated store tests; `make build/test/lint` green is the completion bar. Do NOT set `PILOT_CONSOLE_E2E=1`; deliver the e2e as env-gated code only — the operator runs it deliberately (same operator pre-steps as the B6 e2e: role grants for `/tenants/*` SSM + KMS decrypt + S3 binary object; documented in `provisioner_e2e_test.go`'s header, reference them, don't duplicate).

**Verify-before-relying**: confirm `SetObservedState` refreshes `updated_at` (the staleness clock depends on it); if it doesn't, make it do so in this PR (needs no new migration — it's an UPDATE-statement change) and cover it in a store test.

**Scope fence (out of scope, do not build):** sleep/wake scheduling (B7 — needs the board-sync wake signal), config render/push + `pilot-apply-config` + acting on `config_generation` drift (B8), AMI-replacement / `upgrading` transitions (B9 rolling upgrade), snapshot-retention + Stripe-driven suspend/terminate (B10 — this task's terminate is the minimal teardown), DLM policies (B11), any HTTP API surface for fleet ops (no auth story yet), instance proxy (C13), CDK/VPC work, metrics endpoints (C15 owns Prometheus).
