# GH-5351

**Created:** 2026-09-07

## Problem

GitHub Issue GH-5351: fix(autopilot): complete #5348 — own close must not be treated as external (persisted marker), superseded only on fix-PR merge with file overlap, no-SHA fallback, worktree-from-SHA test

## Context

Post-merge review of PR #5349 (issue #5348): items 1–3 landed well — the fix-issue footer carries `sha:`, the handler parses it into `Task.FixFromSHA`, and the worktree base resolves to the live remote branch or a fetched SHA (`internal/executor/git.go` ~1427-1463, `internal/executor/runner.go` ~2837-2878) with escalation when unfetchable. That makes the #275 outcome non-reproducible in the common case. Two spec items were not implemented and one was inverted; this issue completes them. Single PR, in this order.

## Implementation

1. **Own close is not an external close (spec item 4).** `internal/autopilot/controller.go`: `markSelfClosed` (~9535) exists with zero callers. Call it in `handleCIFailed` before the close at ~3838 (and the two sibling close sites ~3673, ~3772 when a fix issue was spawned). Persist the marker on the PR state row (a `self_closed_at`/`fix_issue` field) instead of the in-memory 10-minute map (~9540-9543), so a daemon restart between close and next poll does not lose it. The external-close watcher (~9364-9399) skips PRs carrying the marker: no `notifyExternalClose`, no `pilot-superseded`, no `finalizeExternalClose` branch deletion (~9445-9468). Branch deletion for such PRs happens when the fix PR merges or the original issue is closed by a human.
2. **Superseded needs delivery evidence (spec item 5).** Drop `TerminalLabel = LabelSuperseded` at spawn (`spawnFailureIssue` ~3482). Record the original PR's changed-file set on the PR state at spawn. Move superseded-labelling of the original issue into `handleMerging` behind the file-overlap check that `verifyFixPRDeliversSourceScope` (`internal/autopilot/owner_death.go` ~158-232) already performs; keep that function as the check, but as a gate before labelling, not a post-hoc revert. API errors in the check must fail closed (no label) with a WARN, not open.
3. **No-SHA fallback (defect 4).** In `runner.go` ~2837, for any task with `FromPR > 0` and empty `FixFromSHA` (pre-#5348 fix issues, or blanked HeadSHA), still call the resolver with an empty SHA so `origin/<branch>` is used when alive; only the "no SHA and no live branch" case may fall back to the default base, and it must log that fallback at WARN with the task id.
4. **End-to-end test (spec item 6 bullet 1).** Create a worktree from a SHA base after the remote branch was deleted and assert the original files are present in the worktree and in the resulting diff against main; current tests only assert the resolved ref string.
5. Cleanup: stale comment at `git.go` ~1421 and the "falling back to default worktree base" WARN at ~1448 (the caller escalates now); `parseAutopilotSHA` should accept only 7–40 hex chars.
