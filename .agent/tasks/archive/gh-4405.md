# GH-4405

**Created:** 2026-07-17

## Problem

GitHub Issue GH-4405: fix(executor): epic close/label/comment pass prefixed task id to gh CLI — 'invalid issue format: GH-N' silently kills epic side-effects

## Symptom

Epic helper paths shell out to `gh` with the **prefixed** task id (`GH-8`, `GH-95`) where the CLI requires a bare issue number. Three distinct call sites failed today (2026-07-17):

```
10:13:24 msg="Failed to close parent issue"  error="failed to close issue GH-95: exit status 1 (stderr: invalid issue format: \"GH-95\")"
11:10:42 msg="failed to label parent with pilot-needs-clarification after coverage gap" parent_id=GH-8 error="gh issue edit: exit status 1 (stderr: invalid issue format: \"GH-8\")"
11:10:42 msg="failed to post coverage-gap comment on parent" parent_id=GH-8 error="gh issue comment: exit status 1 (stderr: invalid issue format: \"GH-8\")"
```

## Consequence

Epic close/label/comment side-effects silently degrade to WARN: parents never get closed after completion, never get `pilot-needs-clarification` on coverage gaps, and never get the explanatory comment — so failures are invisible on GitHub and epics look stuck for no reason.

## Fix sketch

Strip the task-id prefix (or use the numeric issue number field already available on the task) at these `gh issue close/edit/comment` call sites in the epic executor paths. Add a unit test asserting bare numbers are passed. Grep for other `gh issue`/`gh pr` call sites fed from `task_id` rather than issue number.
