## Problem

GitHub Issue GH-3991: feat(autopilot): label-scope reconciler — scope:<name> completion triggers the scope release

Part of TASK-389 (release cycles). Second scope kind: sibling issues grouped by a shared `scope:<name>` label (no epic parent) — e.g. TASK-388's 3 dependency-chained issues.

## Implementation

NEW `internal/autopilot/scope_reconcile.go`:
- `reconcileLabelScopes(ctx)` on the `epicParentTicker` case (next to `reconcileEpicParents`), capped like `maxEpicReconcile`.
- Enumerate candidate labels: one GraphQL query `repository { labels(query: $prefix, first: 50) { nodes { name issues(states:[OPEN], first:1){ totalCount } } } }` (ExecuteGraphQL precedent: epic_reconcile.go ~:72). Prefix = resolvedRelease().ScopeLabelPrefix (default "scope:"). Labels with open issues → skip (Debug log).
- Zero-open candidates: cheap table check FIRST (`ListScopeReleases` — done/failed → skip before any further API); then fetch all issues carrying the label (GraphQL in-package `labels -> issues(states:[OPEN,CLOSED], first:100)`, cap 100 + WARN — do NOT add SDK methods). Bound by `ScopeLookback` on the newest closed_at (pre-feature completed scopes never enqueue).
- Completion gate (mirror `verifyChildrenShippedForClose`, epic_reconcile.go ~:96-125): every closed member must have a merged PR (`SearchPRsForIssue` + pr.Merged) or verified no-op ledger row (`isChildNoOp`, controller.go ~:1998). Closed-member-without-PR → VETO the scope (log). Per-member search error → fail-open for that member's notes, don't veto.
- Complete → `enqueueScopeRelease("label:<name-sans-prefix>", "<name>", mergedPRs)` — #3990's machinery does the rest.
- Abandoned-scope alert: ≥1 shipped member + ≥1 open member untouched > `ScopeStaleAfter` (new ReleaseConfig field, default 168h) → alert `scope_stale`, deduped per key in a controller map (pattern: `alertedMissingReleases`).

## Edge cases (state in code/docs)

- Single-issue scope → one-PR scope release (by design).
- Label added AFTER members already released per-merge → notes may include already-shipped PRs (documented misuse, not guarded).
- Label renamed mid-flight → orphaned pending row whose members never complete → covered by scope_stale alert.
- >100 issues per label → cap + WARN.
