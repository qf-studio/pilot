## Problem

GitHub Issue #3027: Guardrail: refuse issue creation on repos outside user's configured project list

**Plan**: `.agent/tasks/TASK-286-guardrail-external-repo-issue-create.md`

## Problem

On 2026-05-20, external Pilot user @tenlisboa accidentally pointed his local `pilot start` at the upstream `qf-studio/pilot` repo. The epic decomposer fired 6 duplicate sub-issues (#3021–#3026) with `feat(auth): add OAuth provider integration`. Diagnosis comment: #3021 (closed).

Root cause (verified via code scan): `internal/executor/epic.go:1218` shells `gh issue create` with `cmd.Dir = executionPath` and **zero owner/repo validation**. `gh` infers `owner/repo` from the directory's `origin` remote. A partial guard exists for the parent task (`runner.go:1130` `ValidateRepoProjectMatch`) but is not invoked on the sub-issue path or in `CreatePilotIssue` (adapter).

## Approach

Single chokepoint `internal/executor/repo_guardrail.go::ValidateTargetRepo(ctx, cfg, owner, repo, projectPath) error` invoked from:
- `internal/executor/epic.go:1218` before sub-issue creation
- `internal/adapters/github/issue_create.go:15` (defense in depth)

Bypassable via `PILOT_ALLOW_UNMANAGED_REPO=1` (logs WARN with resolved owner/repo).
