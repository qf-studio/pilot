# GH-5435

**Created:** 2026-09-12

## Problem

GitHub Issue GH-5435: feat(executor): honour 'paste the output into the PR body' acceptance items — run mutation/evidence commands and record them in the PR

## Problem

Six consecutive Pilot PRs on pilot-console and pilot-console-ui today (console PR #298, #301, #302, #304; ui PR #157, #161) shipped with an acceptance item of the form "Mutation checks pasted into the PR body: (a) … → a named test fails" left unchecked and with no output pasted, even after the item was reworded as a hard gate ("a PR without the paste is not done"). In every case the executor did write tests whose names reference the mutation, and in every case the reviewer had to re-run the mutations by hand to get the evidence the issue asked for. The gate exists because green CI is not proof that a pin actually catches the regression it claims to (TASK-460 false-success class); the paste is the artifact that proves the executor ran the mutation and saw the test fail.

Two gaps compound: the executor does not treat "paste X into the PR body" as a deliverable, and nothing on the completion path flags an acceptance checkbox that is still unchecked when the PR is opened.

## Fix

1. Executor: when an issue's acceptance criteria contain an item asking for output to be pasted into the PR body (patterns like "pasted into the PR body", "paste the output", "terminal output"), the executor runs the described commands after implementation, captures stdout/stderr, and appends a `## Evidence` section to the PR body with each command and its trimmed output (cap per block, e.g. 60 lines). Mutation-style items ("change X → test Y fails") are executed as: apply the described change on a scratch copy of the working tree, run the named test or package, record the failing test names, revert. If a mutation does not fail any test, the executor must say so in the PR body instead of omitting it — that is a real finding for the reviewer.
2. Completion gate: before opening the PR, compare the issue's acceptance checklist to the PR body; any acceptance item that requires pasted evidence and has none is reported in the PR body under `## Not verified` with the reason, so a reviewer sees the gap without diffing the issue against the PR.
3. Keep this behind a config flag defaulting to on for repos that already use the acceptance-checklist convention; document the patterns recognised.

## Acceptance

- [ ] A test issue with a "paste the output of `go test -run TestX ./pkg/`" acceptance item yields a PR body containing that command and its output
- [ ] A mutation-style item ("delete line L → TestY fails") yields the failing test name in the PR body, and the working tree is left clean afterwards
- [ ] A mutation that fails no test is reported as such, not omitted
- [ ] Acceptance items requiring evidence that could not be produced appear under `## Not verified`
- [ ] Unit tests for the acceptance-item pattern detection and for the evidence section rendering; no executor path changes when the flag is off

## Planned Steps (execute all in sequence)

- Step 1: **feat(executor): detect acceptance-evidence items, run mutation/paste commands, and gate PR body with results** — In internal/executor/: (1) Pattern detection — add a parser walking the issue's acceptance checklist (Markdown `- [ ]` items) classifying each as paste-output (matches 'pasted into the PR body', 'paste the output', 'terminal output', extracting fenced/inline commands), mutation (matches 'change …', 'delete line …', 'remove …' followed by '→ … fails' / 'test … fails', extracting the mutation description + named test/package), or other (ignored); include table-driven unit tests for positive/negative patterns, multiple commands per item, and language variants. (2) Evidence runner — for paste-output items, run each command via the executor's existing shell/exec plumbing inside the worktree, capture stdout+stderr, trim to ≤60 lines per block with a truncation marker; for mutation items, snapshot the worktree (git stash or copy), apply the described change (LLM-assisted for freeform mutations, mutation string is source of truth), run the named test/package, record failing test names, then revert; if revert leaves the worktree dirty, abort and record the gap under '## Not verified' (never push a dirty tree); if a mutation fails no test, record verbatim ('mutation applied; no test failed') rather than omitting. (3) PR-body rendering — append a '## Evidence' section listing each acceptance item, command(s) run, and trimmed output in fenced blocks; append a '## Not verified' section for acceptance items requiring evidence but lacking it (with reason: no commands parsed, execution error, revert failure); preserve existing PR body content above these sections. (4) Completion gate — extend the pre-PR-open path (near gate.go / PR body assembly) to diff the issue's acceptance checklist against the produced PR body; any evidence-requiring item without a matching Evidence block gets a '## Not verified' entry before the PR opens; never block PR creation on missing evidence, just surface it. (5) Config flag — add a bool (executor.acceptance_evidence.enabled) in internal/config/config.go, default true, wired through the runner; when off, none of the above executes and PR-body assembly is byte-identical to today (verified by a test). (6) Docs — brief note in configs/pilot.example.yaml listing recognised patterns. (7) Tests — unit tests for pattern detection, evidence-section rendering (golden PR body), mutation harness revert-on-panic, flag-off no-op, and an end-to-end test feeding a synthetic issue with one paste-output item and one mutation item through the assembly path. Kept as a single subtask because splitting detection, mutation harness, PR-body rendering, and the completion gate across parallel subtasks would collide on the same runner/PR-body code paths.
