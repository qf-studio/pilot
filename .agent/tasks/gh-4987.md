# GH-4987

**Created:** 2026-08-19

## Problem

GitHub Issue GH-4987: feat(jira): merge-side done leg — transition the card + completion comment when the PR merges (KAN-6 stuck in To Do forever)

## Problem

The Jira merge-side close leg does not exist. Live-verified 2026-08-19 against the KAN-6 e2e card (`quantflowstudio.atlassian.net`, first real tracker-to-PR chain, PR #4955 merged 08-18 17:34Z):

- Card status: still **"К выполнению"** (To Do), resolution `None`, labels `[pilot, pilot-done]`, exactly 1 comment (the start comment).
- The start comment's own promise — "_This issue will be closed when the PR is merged._" (`NotifyTaskCompleted` template) — has **no implementation**: nothing in `cmd/pilot` or the autopilot merge path calls the Jira notifier's completed leg. GH-4718 wired only `NotifyTaskStarted` (cmd/pilot/poller_jira.go:77); the `pilot-done` label is applied by the SDK poller at task-completion (PR-created) time, not merge time.
- The in-progress transition also silently failed: the SDK notifier falls back to `TransitionIssueTo(ctx, key, "In Progress")` — name matching can never work on a localized workflow (this site's statuses are Russian).

Net effect: a Jira-tracked task that ships end-to-end leaves its card in the To Do column forever. GitHub-tracked issues get closed on merge; Jira cards get nothing.

## Fix

1. **Merge-side leg**: when the autopilot merge path completes a PR whose task is Jira-originated (`JIRA-<KEY>` task id), call the SDK Jira notifier's done leg: completion comment (PR URL) + transition using `transitions.done` when configured.
2. **Localization-safe fallback**: when no transition ID is configured, resolve via `GetTransitions` and match on the target status **category** (`done`/`statusCategory.key == "done"`), not the English name `"Done"`. Same fix for the in-progress fallback (`indeterminate` category).
3. Notify failures stay WARN-only — never block the merge path.

## Acceptance criteria

- [ ] Merging a `JIRA-*` task's PR posts a completion comment with the PR URL on the card
- [ ] Card transitions to a `done`-category status (config transition ID preferred, category-matched fallback otherwise) — works on non-English workflows
- [ ] In-progress fallback also category-matched
- [ ] Failure to notify/transition is WARN-logged and non-fatal
- [ ] No behavior change for GH-/Linear-originated tasks
