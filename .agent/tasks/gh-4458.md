# GH-4458

**Created:** 2026-07-18

## Problem

Foundation for the rung changes in internal/autopilot/controller.go. Introduce a self-close marker (in-memory set keyed by owner/repo#number with a short TTL, or a pilot-autoclosed label/body sentinel — pick one and justify) that autopilot stamps whenever it closes a PR it owns. Teach the 'PR closed externally' poll path (currently the entry to notifyExternalClose → ReclassifyCompletionAsFailed + branch delete) to treat stamped closes as internal transitions, NOT as human rejection. Only unstamped closes retain the current reclassify + branch-delete semantics (GH-3818/D10 preserved for real external closes). Add a reusable escalateAndHold(pr, reason, labels, comment) helper: sets StageFailed, applies pilot-needs-human (+ caller-supplied labels like needs-manual-rebase), posts a diagnostic PR comment, emits an alert via the existing alert engine, and leaves the PR open with the branch intact. No close, no branch delete, no re-execution trigger. Add table-driven tests in internal/autopilot/controller_test.go (or a new escalate_and_hold_test.go in the same package) covering: (a) stamped self-close is ignored by the external-close handler; (b) unstamped external close still reclassifies + deletes branch; (c) escalateAndHold produces the expected labels/comment/alert without touching the PR state. Verifiable independently: the helper and attribution can be unit-tested without touching any rung.
