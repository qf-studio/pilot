## Problem

GitHub Issue #3691: feat(comms): bot module P4 (redo) — conversational issue intake

## Context

Re-dispatch of P4 (conversational issue intake) for the bot module. The prior PR
(#3685) was built in parallel with P3 and **conflicted** once P3 merged — it
overlapped on `responder.go`/`handler.go`/`config.go`. Build this **fresh against
current `main`**, which already has: `internal/llm`, `BotConfig`, the `Responder` +
fast chat path, and P3's grounded Q&A retrieval (`responder.Answer` + `retrieval.go`).
Add issue intake **on top** — do not re-create those.

Full spec: `.agent/tasks/TASK-376-bot-issue-intake.md`.

No existing logic turns a freeform message into a structured issue. Add a
conversational intake that drafts `title`/`body`/`labels` and **creates the issue
directly + labels `pilot`** (auto-executes). Guardrails: the repo allowlist +
conventional-commit title check in `CreatePilotIssue`
(`internal/adapters/github/issue_create.go:59,63`).

## Implementation

- `internal/comms/issue_intake.go`: `IssueDraft{Title,Body,Labels}`, per-context
  state machine (`pendingIssues` on `Handler`, mirroring `pendingTasks`), and the
  `IssueCreator` interface
  `CreateIssue(ctx, projectPath string, d IssueDraft) (url string, err error)`
  (mirrors `MemberResolver` DI — keeps comms PM-agnostic, no executor→github cycle).
- `internal/comms/responder.go`: ADD a `DraftIssue(ctx, history, msg) (IssueDraft, error)`
  method next to the existing `Chat`/`Answer` — do not modify those. LLM drafts a
  **conventional-commit** title (`type(scope): desc`) + body; default label `pilot`
  when `bot.issue_intake.auto_label_pilot`.
- `internal/adapters/github/issue_creator.go`: concrete `comms.IssueCreator`
  resolving active project → `owner/repo` → `github.CreatePilotIssue(...)` with the
  `pilot` label + `RepoAllowlist`.
- Triggers: new `intent.IntentIssueIntake` (NL "create an issue to…", "file a
  ticket…") in `intent.go`/`classifier.go`, plus `/draft-issue <text>` in
  `commands.go` (pattern: `handleNoPR`/`handleForcePR`).
- `handleIssueIntake` in the `detectIntent` switch in `handler.go`; `cmd/pilot/main.go`
  wires the github-backed `IssueCreator` into `HandlerDeps`.
