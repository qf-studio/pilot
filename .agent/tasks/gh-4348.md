# GH-4348

**Created:** 2026-07-16

## Problem

GitHub Issue GH-4348: fix(canary): tracker comment spam — update one status comment in place + auto-close after 3 green runs (#4265 hygiene)

## Context

The epic-lifecycle stall tracker #4265 accumulated 15 comments in 3 days — 10 of them identical auto-appended "Canary re-triggered ... stalled" notices (one per scheduled failure). The signal (assertion name, canary issue link) drowns in repetition, and the tracker never closes itself when the scenario recovers.

## Problem

`.github/workflows/pilot-canary-scenario.yml` (or the canary reporter it calls) APPENDS a new comment on every failed run to the evergreen tracker issue. There is no update-in-place and no green-streak auto-close.

## Fix

1. **Update-in-place**: maintain ONE bot status comment per tracker issue (find-by-marker `<!-- canary-status -->`, edit it) containing: latest run result, failed assertion(s), canary issue link, and a compact history table of the last ~10 runs (timestamp · assertion · run link). New failure = edit, not append.
2. **Auto-close on recovery**: when the scenario passes N=3 consecutive scheduled runs while its tracker is open, close the tracker with a final status comment (reopen on next failure rather than filing a new issue — keep the evergreen pattern).
3. Keep first-failure behavior (open/reopen the tracker) unchanged.
