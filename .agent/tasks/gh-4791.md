GitHub Issue GH-4791: feat(autopilot): platform-outage breaker part 1 — cross-PR correlation + suppress destructive actions

## Problem

During the 2026-08-06 GitHub Actions outage the daemon acted on false CI signals for ~50 minutes — closing a correct PR, spawning junk fix issues, burning retries — until a human stopped it. Per-PR guards cannot catch this: the existing circuit breaker is deliberately per-PR ("so one bad PR doesn't block others", `controller.go:108-109`) and each PR looked individually normal. The missing signal is **correlation**: several unrelated PRs failing within minutes is a platform event.

This is **part 1 of 2** (split from #4780, which timed out at 1h as a single unit — keep this leg small). Part 2 adds the external status probe, admission pause, and held-PR re-drive.

## Scope — part 1 only

1. **Tracker** following the `internal/ghbudget/ghbudget.go` shape (process-wide state, `Allow`-style gate, exactly-one log per state transition): record each CI-failure observation as `(pr, repo, class, time)`. Open the breaker when ≥N distinct PRs (default 3) observe infra-or-unknown-class failures inside a window (default 15 min). Close it after a quiet period (default 20 min with no new infra-class failure) — simple time-based recovery only.
2. **Consume the classes shipped in #4787** (`FailureClassInfra` / `FailureClassUnknown`, `internal/autopilot/failure_class.go`).
3. **While open, suppress irreversible actions in the CI-failure path** (`handleCIFailed`, `internal/autopilot/controller.go`): no `ClosePullRequest`, no fix-issue creation, no `escalateAndHold`. The PR stays at its current stage and is re-examined on a later tick — polling, board sync, gauges and running executions all continue untouched.
4. **Alert once on open and once on close** with the correlated PR list, following an existing once-per-transition pattern (`alertBillingRefusalOnce`, `controller.go:1216`, or the ghbudget transition-log shape). Never one alert per affected PR.
5. Metrics: breaker-state gauge + trip counter (mirror `RecordCircuitBreakerTrip`).
6. Config on `autopilot.Config` (`internal/autopilot/types.go:142-165` neighbourhood): enable flag + the two thresholds + quiet period; documented in `configs/pilot.example.yaml`. Static at boot is fine (`Config.Reload` has zero callers).
7. Tests: correlation opens across distinct PRs but NOT on 3 failures of one PR (that is the per-PR breaker's job) · destructive actions suppressed while open · time-based close · disabled-by-config is a byte-identical no-op · `-race` clean.
