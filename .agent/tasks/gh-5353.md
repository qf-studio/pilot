# GH-5353

**Created:** 2026-09-07

## Problem

GitHub Issue GH-5353: fix(dispatcher): stalled re-arm loses the race with the SDK poller — escalateStalledTask re-stamps completed_at on the alreadyStalled path

Post-merge review of PR #5343 (issue #5272). The re-arm sweep in `cmd/pilot/rearm_stalled.go` compares GitHub label events against the stalled execution row's `completed_at` and only re-arms when a re-arm label event is strictly newer. But `escalateStalledTask` in `internal/executor/dispatcher.go` (~2416) calls `UpdateExecutionStatus(stalled)` unconditionally, including on the `alreadyStalled` repeat path (~2421), and `internal/executor/store.go` (~2560) sets `completed_at = CURRENT_TIMESTAMP` on every terminal write.

Failure scenario:
1. Operator applies the re-arm recipe at T1 (labels `pilot-retry-ready`).
2. The SDK poller (same 30 s cadence as the sweep, unsynchronized) picks the issue first, labels `pilot-retry-1` at T2a, dispatch hits the hard cap, the stalled row's `completed_at` is re-stamped at T2b ≥ T2a.
3. The sweep now sees every label event ≤ `completed_at`; `latestRearmEvent` returns nil; `recordClaimLostDrop` gates the probe (shared backoff key with the handler's claim-lost drops, up to ~16 min).
4. Every later poller pickup re-stamps again, so the evidence never becomes "after the stall". `InvalidateCompletion` (`store.go` ~1652) only deletes `completed` rows, so it does not rescue this.

The PR's tests seed the stalled row with a fixed timestamp and never interleave a poller pickup, so this path is uncovered.

## Fix

1. In `escalateStalledTask`, do not call `UpdateExecutionStatus` when `alreadyStalled` is true (no state change, no timestamp change). Alternatively, make the sweep compare against the earliest stall stamp (first time the row entered `stalled`), not the latest write.
2. Keep the log fields added by #5343.
3. Correct the claim-lost log level to WARN at both sites (`dispatcher.go` ~2565, ~2632) so it matches the issue/PR text, or update the docs to say Info.

## Tests

- Interleaving test: stalled row at T0 → re-arm label event at T1 > T0 → simulated poller pickup that re-runs `escalateStalledTask` on the already-stalled row at T2 > T1 → sweep must still re-arm (evidence at T1 must remain newer than the stall stamp).
- Negative: `pilot-retry-ready` event BEFORE the stall must not re-arm.
- Negative: `pilot-retry-exhausted` must not re-arm.
