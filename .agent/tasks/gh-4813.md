# GH-4813

**Created:** 2026-08-08

## Problem

GitHub Issue GH-4813: fix(autopilot): post-merge CI rung spawns fix issues on evidenced infra failures — add post-merge infra-retry/hold leg

## Context

TASK-459 Phase 2 (PR#4812) added classification + `Verdict` gating to the post-merge CI-failure rung in `handlePostMergeCI` (`internal/autopilot/controller.go` ~:4053-4130): zero-evidence now holds instead of spawning. Post-merge review of PR#4812 found the residual gap this issue closes.

`Verdict.AuthorizesDestructive()` is deliberately class-blind — any non-Unknown class with evidence authorizes. Pre-merge that is safe because `maybeRetryInfraFailure` intercepts infra-family classes upstream of every destructive rung. **The post-merge path has no infra-retry leg**, so an *evidenced infra-class* post-merge failure (e.g. a runner 503 in the check logs) flows straight to `CreateFailureIssue` — a junk code-fix issue for a failure that is GitHub's, not the repo's (the #4766/#4769/#4775 incident shape, surviving on the post-merge rung only). The platform breaker mitigates only once 3+ distinct PRs correlate; a lone post-merge infra flake spawns anyway.

This is pre-existing behaviour (not a Phase 2 regression) — but Phase 2 landed `postMergeVerdict` at that exact site, so the class is now available to branch on.

## Task

In `handlePostMergeCI`'s CIFailure branch: when `postMergeVerdict.Class().IsInfra()`, do not spawn a fix issue. Choose the non-destructive path:

- **Preferred**: rerun the failed post-merge jobs (the post-merge analog of `maybeRetryInfraFailure`/`rerunInfraFailures` on `mainSHA`), with the same bounded budget semantics (`maxInfraRerunBudget` or a post-merge equivalent keyed to the SHA) so a persistent failure still escalates.
- **Fallback if rerun plumbing doesn't reach the post-merge SHA cleanly**: `escalateAndHold` with a distinct reason ("post-merge CI failure classified infra") rather than spawning — a human sees it; no executor dispatch is burned.

Either way: `FailureClassInfraBilling` keeps its existing alert path (`alertBillingRefusalOnce` shape) if reachable post-merge.
