# GH-5460

**Created:** 2026-09-25

## Problem

GitHub Issue GH-5460: fix(executor): hook cleanup leaves a dangling pilot-bash-guard entry and an untracked .claude/settings.json in root-mode execution

## Problem

When Claude Code hooks are enabled (GH-1266), the runner writes the Pilot bash-guard hook into the execution path's .claude/settings.json (created at runtime, not in the repo) pointing at a temp dir /tmp/pilot-hooks-RAND/pilot-bash-guard.sh (temp dir, created at runtime), and registers `hookRestoreFunc` (`internal/executor/runner.go` ~L4404-4415) to undo it. The restore closure calls `CleanStalePilotHooks(settingsPath)` **and then** `os.RemoveAll(scriptDir)`. `CleanStalePilotHooks` only removes entries "whose script files are gone" (`hooks.go` ~L487). At that moment the script still exists, so the entry is kept; the directory is deleted right after. Result: a dangling hook entry survives every task.

On the founder box this is invisible because `use_worktree: true` discards the worktree. On a hosted tenant (rendered config has no `use_worktree`, so execution runs in the project root) the effect after the first task, observed 2026-09-25 execution `6402c4d9`:

- project root has an untracked .claude/settings.json with a hook pointing at a deleted temp dir;
- `finish_tripwire_root_clean` fires on every task from then on;
- `gh pr create` prints `Warning: 1 uncommitted change`, which corrupts `pr_url` (separate issue);
- the next Claude Code session in that root loads a hook whose command does not exist.

The start-of-task cleanup (runner.go ~L4359) does remove the stale entry on the *next* run because the script is gone by then, but leaves the file (`{"hooks":{}}` or an empty `PreToolUse` array), so the root stays dirty.

## Fix

In `hookRestoreFunc`: remove the script directory first, then call `CleanStalePilotHooks`; or better, have the cleanup remove entries whose command path is under the current run's `scriptDir` regardless of existence. After cleanup, if Pilot created .claude/settings.json for this run (it did not exist before `MergeWithExisting`) and the file is now semantically empty (no hooks left, no other keys), delete the file and the `.claude/` directory if empty. `MergeWithExisting` already knows whether the file pre-existed; surface that to the caller.

## Acceptance criteria

- After a task finishes in root mode with hooks enabled and no pre-existing .claude/settings.json, the project root is `git status --porcelain` clean.
- With a pre-existing user .claude/settings.json, the user's content is byte-identical after the task and the Pilot entry is gone.
- Unit test on the restore path: entries under `scriptDir` are removed even when the directory still exists at cleanup time.
- No change when hooks are disabled.
