# feat(github): TASK-461 Leg 2 — SDK clients resolve tokens per request (App-cutover wiring)

## Context

Under GitHub App auth, installation tokens expire hourly. The in-tree client family already resolves per request (GH-4743 `TokenSource` · GH-4747 `githubTokenFunc`/`newGitHubClient`, `cmd/pilot/main.go:225-267` · GH-4754 401-invalidate-retry · GH-4778/PR#4789 residual sites). The **studio-sdk** clients still freeze the boot token for the daemon's lifetime.

The SDK side is complete:
- sdk#107 → sdk PR#108 (in v0.32.0): `TokenFunc`, `NewClientWithTokenFunc(fn, opts...)`, `WithTokenInvalidate(fn)` — token resolved per request attempt inside the retry loop; 401 runs the invalidate hook once, then retries once.
- sdk#109 → sdk PR#110 (merged 2026-08-09, **not yet in any tagged release** — v0.32.0 predates it): `New(cfg, ...AdapterOption)` + `WithAdapterClient(*Client)` injection seam, nil-safe; the adapter's Poller, MergeWaiter, and board sync/source all inherit the injected client.

`resolveGitHubToken` (`main.go:181`) already mints through the App `TokenSource` cache when `adapters.github.app` is configured, so per-request calls are cache hits, not fresh mints.

Line refs verified on main @ `39881bba` (2026-08-10). If drifted, re-trace from function names.

No tagged release contains PR#110 (v0.32.0 is older) — pin its merge commit: `go get github.com/qf-studio/studio-sdk@2e0f01e96720adc0572a4d162cf9109adfc3d329` (resolves to a pseudo-version; the current pin `v0.31.2-0.20260721...` shows this is established practice), or a newer tagged release if one exists at implementation time.
2. **Shared constructor**: `newGitHubSDKClient(cfg *config.Config) *githubSDK.Client` beside `newGitHubClient` (`main.go:265`): `githubSDK.NewClientWithTokenFunc(githubSDK.TokenFunc(githubTokenFunc(cfg)), ...)`. `invalidateGitHubAppToken` returns nil when App auth isn't configured — the SDK treats a nil hook as no-retry (safe), but pass `WithTokenInvalidate` conditionally to keep intent explicit.
3. **Swap the daemon-lifetime sites** to the shared helper: `main.go:826`, `main.go:~2085`, `main.go:~2541`, `poller_github.go:478`, `handlers.go:770`.
4. **Poller fan-out**: construct ONE shared client in `githubPollerRegistration.CreateAndStart`, thread it through `startGithubSDKPollerForRepo` (replacing the `token string` param), inject via `githubSDK.New(sdkCfg, githubSDK.WithAdapterClient(client))`. One client across the fan-out matches today's one-token-shared design (rate-limit budget is per-credential).
5. **Boot fail-loud gate stays** (`poller_github.go:228-240`): keep the empty-resolve check, but run `verifySDKGithubToken` against the shared TokenFunc-backed client so the verified path is the production path.
6. **Comment parity**: update the "studio-sdk client … until later phases" comments at `main.go:824-826`/`~2083-2085`.

No-App-config path behavior byte-identical (static token resolved per request yields the same token every time).
