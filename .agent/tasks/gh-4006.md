# GH-4006

**Created:** 2026-07-07

## Problem

GitHub Issue GH-4006: fix(autopilot): epic parent re-dispatch loop when close-veto is permanent — add loop breaker + escalation

## Context (live instance today)

Epic parent #3927 entered an infinite re-dispatch loop: **6 completed executions in ~2h** (11:39, 12:14, 12:19, 12:25, 12:30, 12:36, re-queued 13:29) with the issue never closing. Broken manually by closing the parent.

Mechanism — two correct behaviors composing into a loop:
1. Child #3952 was **ghost-closed** (closed as "completed as part of GH-3927" while its PR #3955 was closed unmerged; the work later shipped under a DIFFERENT issue's branch, #3956 → PR #3980).
2. `verifyChildrenShippedForClose` (epic_reconcile.go) correctly **vetoes** the parent auto-close: closed child, no merged PR, no no_op ledger row → parent stays open. Working as designed.
3. The poller sees an open `pilot`-labeled issue with no open children → re-dispatches the parent. The execution completes (nothing to do), the issue stays open, next poll re-dispatches. Forever.

The veto is right; the missing piece is a **loop breaker** when the veto is permanent.

## Task

When epic-parent reconciliation vetoes a close AND the parent keeps getting re-dispatched, break the loop instead of burning tokens:

1. Track consecutive vetoed reconcile passes per parent (in-memory map + the execution ledger already records the parent's completed runs — use whichever is simpler/restart-safe enough).
2. After N (suggest 3) completed parent executions while the close-veto persists: add `pilot-needs-clarification` (or a dedicated `pilot-blocked-close` label), post ONE comment explaining exactly which child fails the shipped-check and why (child number, its close state, missing merged PR), and stop re-dispatching (the clarification label already excludes issues from dispatch).
3. The comment must name the recovery: human either closes the parent manually, or fixes the child linkage (e.g. a `Shipped via: #<other-issue>` / merged-PR reference the verifier can follow — if you add such a body-marker escape hatch, document it; optional, keep v1 minimal).
4. Alert once (`epic_close_vetoed` or reuse existing alert types) so it's loud, not just labeled.

## Evidence

- #3952 ghost-close chain: close comment "Completed as part of GH-3927 / PR #3955" → #3955 closed unmerged → work shipped via #3956 → PR #3980
