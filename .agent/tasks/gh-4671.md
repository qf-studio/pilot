# GH-4671

**Created:** 2026-08-04

## Problem

GitHub Issue GH-4671: feat(executor): gh-guard shim — intercept executor gh calls at the Bash boundary, allowlist subcommand+target, deny sibling-issue/cross-repo mutations

## Context

Durable leg of the GH-4649 containment (record: `.agent/tasks/TASK-437-duplicate-execution-race-prevention.md`; cheap advisory+detective pair: #4670). Facts (verified at `c5208a87`): executor children spawn with `--dangerously-skip-permissions` on all paths (`internal/executor/backend_claudecode.go:489/502/513`), inherit the full daemon env incl. the org-spanning `GITHUB_TOKEN` (`:575`), and Bash has no subcommand filter — the LLM's `gh` calls have NO interception point. Prompt rules (#4670) are advisory; this issue adds the **preventive** boundary without touching the permission flag.

**Design — `gh` guard shim via PATH, arg-parsing in Go:**

At spawn, prepend a per-execution shim directory to the child's PATH containing `gh` → the pilot binary in a guard mode (`pilot gh-guard`), which parses argv in Go (never shell parsing), applies policy, and on allow `exec`s the real `gh` (real path via env var). Task identity reaches the guard via env: `PILOT_TASK_ISSUE`, `PILOT_TASK_REPO`, `PILOT_TASK_BRANCH`, `PILOT_GH_REAL`.

Policy:
- **Allow, unconditional**: read-only commands — `gh issue view/list`, `gh pr view/list/checks/diff`, `gh run view/list`, `gh api` GET-only (no `-X`/`--method` other than GET), `gh auth status`.
- **Allow, own-artifact**: `gh pr create` (head must be `PILOT_TASK_BRANCH`), `gh issue comment`/`gh pr comment` targeting exactly `PILOT_TASK_ISSUE` or the PR on `PILOT_TASK_BRANCH`.
- **Deny, always**: `gh issue close/reopen/edit/lock/transfer/delete` (any number — lifecycle is system-owned), any `--add-label/--remove-label` (pilot-* labels are poller-load-bearing), any command naming a different issue/PR number, any `-R/--repo` other than `PILOT_TASK_REPO`, `gh release *`, `gh repo *` mutations, `gh api` non-GET, `gh secret/variable/workflow *`.
- **Deny UX**: exit non-zero with a one-line explanation of the rule and what IS allowed (so the session adapts instead of retry-looping) + append a structured line to a guard journal file in the worktree that the post-run audit (#4670) ingests as evidence.
- **Escape hatch**: config flag (`claude_code.gh_guard: true` default) — off restores today's behavior; startup log states the mode.

## Acceptance

1. `pilot gh-guard` subcommand implementing the policy table above; argv classification is a pure function, exhaustively table-tested (allow/deny/own-artifact vectors incl. flag aliases `-R`/`--repo`, `--method`/`-X`, issue-number extraction from positional args and URLs).
2. Spawn integration in `backend_claudecode.go`: shim dir created per execution (worktree-scoped, cleaned with it), PATH prepended, `PILOT_TASK_*`/`PILOT_GH_REAL` env set; applies to all three arg branches. Real `gh` resolved at daemon start (absolute path), not from the child's PATH.
3. Guard failures are safe: if the shim can't resolve real `gh` or env is incomplete → fail CLOSED for mutations, fail OPEN for reads, log once.
4. Deny events land in the guard journal; the #4670 audit (or its event type, if #4670 already merged) picks them up — evidence trail per invariant "never act silently".
5. Config flag + startup log line; `configs/pilot.example.yaml` documented.
6. Regression test at the spawn layer: fake execution asserts PATH order, shim presence, env completeness; e2e-style test invoking the shim binary against a fake `gh` (a script recording argv) for one allow + one deny path.
7. `make build`, `make test`, `make lint` green.

## Implementation

Files: `cmd/pilot/ghguard.go` (subcommand, thin) + `internal/executor/ghguard/` (policy pure-core + tests) + `backend_claudecode.go` spawn wiring + config. Keep the policy table data-driven (one struct slice) so future allows are one-line diffs. Note darwin/Linux both must work (shim is a symlink or tiny script exec'ing `pilot gh-guard -- "$@"` — pick the portable option and say why).

Out of scope: removing `--dangerously-skip-permissions` (bigger posture change), branch protection (founder decision), network-level egress control, prompt text (#4670).
