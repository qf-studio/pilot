**Created:** 2026-08-06

## Problem

GitHub Issue GH-4756: feat(gateway): enforce bearer auth on /api/v1 in production when a gateway token is configured (PR#4752 review)

## Problem

The gateway's bearer auth exists (`Authenticator.Middleware`, `internal/gateway/auth.go:102`) and PR#4752's composed test asserts 401s — but production never enables it: routes are wrapped only when `s.auth != nil` (`internal/gateway/server.go:244-249`), and the only non-test callers of `NewServerWithAuth` are `NewServer` itself (passing nil) and tests. Both production construction sites — `internal/pilot/pilot.go:441` (gateway mode) and `cmd/pilot/main.go:2242` (polling mode) — use `NewServer`, so the deployed daemon serves `/api/v1/` with no auth middleware at all. PR#4752 put the first state-mutating endpoint (approving a pre-merge gate) on that surface.

Today's mitigant is the default `127.0.0.1` bind (`internal/config/config.go:445`). But hosted instances must bind reachable-from-console, and the console proxy ALREADY sends `Authorization: Bearer <PILOT_GATEWAY_TOKEN>` (pilot-console `internal/proxy/proxy.go:336`, per-org SSM SecureString) that the daemon currently ignores. Any network peer that can reach a non-loopback gateway can approve PR merges.

## Acceptance

1. A config field enables auth: verify what the existing `Authenticator` binds to first; if nothing, add e.g. `gateway.auth_token` with an env override. When non-empty, BOTH production construction sites (gateway mode + polling mode) build via `NewServerWithAuth` — the GH-4738 lesson: wire both, prove it with a composed test.
2. Empty token → current behavior exactly (no auth, loopback default) — fully backwards compatible.
3. Hosted-path check: confirm the tenant config render (pilot-console `internal/fleet/configrender.go`) can carry the same `PILOT_GATEWAY_TOKEN` the console proxy sends; note in the PR description if a console-side follow-up is required (do NOT change the console repo here).
4. Composed wiring test: token configured → 401 without bearer on a read route AND the decision route; correct bearer → 200.
5. `make build` / `make test` / `make lint` green.
