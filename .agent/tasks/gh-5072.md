# GH-5072

**Created:** 2026-08-21

## Problem

GitHub Issue GH-5072: fix(dispatch): parked needs-human issue is re-picked every poll cycle with an uncached LLM preflight — arm repickBackoff on the needs_human skip (PR#5064 residual)

## Summary

PR#5064's needs-human admission check holds the park, but the parked issue stays a **hot candidate**: the studio-sdk bridge drops `Skipped`/`SkipReason` when converting `core.IssueResult` → github `IssueResult` (sdk v0.35.2 `adapter.go:98-113`; the github struct has no such fields, poller.go:35-42), so the host's skip reads as "failed without PR" → `unmarkProcessed` + board Retry churn. Every poll cycle the issue is re-picked and pays a fresh `GetIssue` + **`passesPreFlight` LLM judge call** (uncached, runs before the handler — poller.go:1132). Sequential mode is worse: no sleep on that path, so `findOldestUnprocessedIssue` can loop the judge at its own latency.

Why nothing else stops it: the sdk candidate filter still ignores `pilot-needs-human` (known gap, sdk leg deferred); the park's `skipped` row doesn't satisfy `HasTerminalCompletion` (only completed/no_op-clean/canceled); and the admission check returns **before** `handler_common.go:198`'s `repickBackoff.allow`, so the GH-4391/GH-4469 backoff machinery — built for exactly this loop shape — never arms.

## Fix (host-side, no sdk change)

In the needs-human skip path at the dispatch chokepoint (`cmd/pilot/handlers.go` ~:729): arm the repick backoff for the task before returning (same idiom as the existing `repickBackoff.allow` consumers), so subsequent cycles suppress the re-pick — zero API + zero judge cost while parked. On label resolution (needs-human removed → issue becomes admissible), the normal backoff-expiry/reset path must re-admit it; verify and pin that with a test rather than assuming.

Nit fold-in: use a named constant for `SkipReason: "needs_human"` (registry.go:62 documents the `sdk/util/skipreason` expectation; a local const is fine until the sdk field survives the bridge).
