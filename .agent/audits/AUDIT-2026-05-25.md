## 0. Executive summary

Pilot is shipping working software at high cadence (v2.149.x = 4 patches in ~24h) but the audit surfaces three systemic issues underpinning most of the recent incidents:

1. **No single source of truth for "task completed."** Six call sites compute the same predicate against different fields (`executions.status`, `commit_sha`, `pr_url`, `pilot-done` label, PR `merged`, `isParentDone`). v2.149.3 hardened the post-flight notifier; TASK-288 documents that the pre-dispatch poller predicate still allows the same false positives through. This is the #1 recurring bug class and is wired into the dispatch-loss class that hit GitNation on 2026-05-21.
2. **God objects + scanner-gate ordering as accident-prone surface.** `internal/executor/runner.go` is 4,556 lines with 111 methods on one `Runner` struct. `cmd/pilot/main.go` has a 1,400-line `runPollingMode`. `internal/autopilot/controller.go` has 5+ handler functions over 100 lines. Multi-gate scanners (`ScanRecentlyMergedPRs`, `checkForNewIssues`) grew gates incrementally with no phase discipline — every observability/metric commit risks landing on the wrong side of a skip gate (see `b140e441`, `6df99408`).
3. **Silent skip is the default operational mode.** Guards return `continue`/`return` with at most a Debug log; multiple multi-hour outages (workshop demo, GH-2301, 2026-04-17) required source-code reading to root-cause. There is no metric for poller skip-by-reason, no counter for repo-allowlist bypass, no panic-recovery wrapper on any production goroutine, and `Metrics.RecordAPIError` is dead code (`pilot_api_errors_total` always emits zero).

Secondary themes:
- **Documentation drift is severe.** CLAUDE.md still claims `v2.53.0 | 316 features` (96 minors stale); FEATURE-MATRIX frozen at v2.53.0; ARCHITECTURE.md frozen at v2.56.0; `--autopilot=` documented as primary CLI flag in 4 places but it's a hidden alias for `--env=`. At least two Navigator pitfall memories cite live code locations for fixes that already shipped.
- **Default-off operational hardening.** Smart retry, stagnation detection, subprocess RSS caps, alerts engine, autopilot itself — all default to disabled. Newly-onboarded users get the un-hardened experience by default.
- **Adapter polling is triplicated.** GitHub/GitLab/Azure DevOps pollers share ~90% structure (~3,000+ LOC of near-duplication); a fix to one doesn't propagate.
- **Test surface is enumerative, not structural.** Tests reproduce the exact reported scenario (good) but rarely assert invariants across all call sites (bad). The repeat GH-201 fixes are the canonical example: 4 negative cases added across 2 PRs, none covering the round-trip path.

**Findings: 178 total**
- P1: 28 — critical (active prod risk, regression magnet, silent failure mode)
- P2: 79 — significant (fragile pattern, missing guard, complexity hotspot)
- P3: 51 — refactor candidate / tech debt
- P4: 20 — nits, naming, comment hygiene

## 1. Cross-stream convergent findings

The findings below were independently surfaced by 2+ research agents using different lenses. High-confidence, high-leverage.

### CS-1. ★ "Completed" predicate inconsistency across 6+ sites — `[P1]`
- Surfaced by: Stream 1 (P1), Stream 5 (P2 swallowed-error variant), Stream 6 (#1 recurring bug class)
- Files: `internal/memory/store.go:540-551`, `internal/adapters/github/poller.go:1022-1037`, `cmd/pilot/handlers.go`, `cmd/pilot/commands.go:1165`, `internal/autopilot/controller.go`, `internal/executor/dispatcher.go:208,249`
- Root: No `executor.IsTaskShipped(row)` predicate; each site composes SQL/label/state differently. v2.149.3 hardened the post-flight notifier but did NOT update `HasCompletedExecution` symmetrically. Per TASK-288, the same false-positive rows that the notifier now rejects still trigger silent dispatch skip on every 30s poll tick.
- Impact: Cleanly-installed v2.149.3 can silently stop dispatching after a single legacy false-complete row. The 2026-05-21 GH-21/22/26 incident lost dispatch for ~5h.
- Fix: Extract `func IsTaskShipped(row Execution) bool` requiring `(commit_sha != "" OR pr_url != "")` AND status=completed; route both the post-flight notifier (cmd/pilot) and pre-dispatch poller (memory/store.go) through it; add a cross-site invariant test asserting both decisions agree on the same row.

### CS-2. ★ Closed-parent / stale-state dispatch loop — `[P1]`
- Surfaced by: Stream 6 (#2 recurring bug class, OAuth cascade incident), Stream 1 (P3 `testing` import in epic.go reflects ad-hoc gating)
- Files: `internal/executor/epic.go` (12 fix commits in last 150), `internal/executor/dispatcher.go:639`, `cmd/pilot/handlers.go:232`
- Recent commits: `d659d73e` (GH-201 fix #1), `59c1d252` (residual hole), `0f1829a8`, `30f91ec9`, Apr 2026 OAuth cascade (`891affe3..424b0198` — 10 revert commits, 64 duplicate sub-issues, 19h)
- Root: `Task` is a snapshot of GitHub state at queue time; dispatcher reconstructs from `executions` rows that don't carry `task_state`. Every entry point must call `isParentDone` defensively, and several have forgotten.
- Fix: Add `task_state` column to `executions`; refresh from live on dispatcher reconstruction; centralize gate behind `MustParentBeActionable(task)` chokepoint with build-tag enforcement.

### CS-3. ★ Production goroutines have zero panic recovery — `[P1]`
- Surfaced by: Stream 5 (P1), Stream 2 (related: `goroutine leaks (go func() without cleanup)`)
- Files: `internal/autopilot/controller.go:1700`, `internal/executor/parallel.go:129`, `internal/executor/runner.go:2892,2902`, `internal/webhooks/manager.go:78`, `internal/executor/dispatcher.go:437`, `internal/adapters/github/poller.go:1127`, `internal/gateway/server.go:247`, `internal/executor/backend_claudecode.go:459,506,544,608,621`, `internal/executor/backend_qwencode.go:284,328,362,409,422`, `internal/executor/rss_sampler.go:20`, `internal/approval/manager.go` (cancel goroutine)
- Issue: 0 `recover()` calls in production. A nil-deref in any adapter callback, RSS sampler, or worker brings the whole daemon down.
- Impact: Any panic in a subordinate subsystem crashes the binary and loses every in-flight task plus the alerting pipeline.
- Fix: Add `safeGo(fn)` helper in `internal/logging` that defers `recover()`, logs with stack at Error, increments `pilot_panics_total{component}`; replace all production `go func(){…}()`.

### CS-4. ★ Silent skip is the default operational mode — `[P1]`
- Surfaced by: Stream 5 (P1 poller skip-by-reason), Stream 6 (silent skip/disable bug class), Stream 7 (`--autopilot` flag drift = silent deprecation)
- Files: `internal/adapters/github/poller.go:919-1040` (9 skip branches, none counted), `internal/executor/repo_guardrail.go:81-94` (bypass logs Warn only, no metric/alert), `cmd/pilot/main.go:1406,2265` (autopilot silently disabled until `f032689b`)
- Root: New gates default to silent `continue`. No convention, no lint, no Prometheus counter for "skipped because X". Operations debugging cost is high.
- Fix: Add `pilot_poller_skipped_total{repo, reason}` + `pilot_poller_dispatched_total{repo}` counters; add `pilot_repo_guardrail_bypass_total{owner, repo}` counter + dedicated `AlertTypeRepoGuardrailBypass` rule; introduce `logSkip(reason, fields)` helper + grep CI check that flags `continue` inside polling loops without preceding log call.

### CS-5. ★ Destructive git operations + half-finished SOP — `[P1]`
- Surfaced by: Stream 6 (P1), Stream 1 (no architectural callout but confirms the file)
- Files: `internal/executor/worktree.go:349` still does `reset --hard` with "safe because tmpdir" comment; SOP at `.agent/sops/git/never-reset-hard-in-automated-flows.md`; v2.146.7 fixed `syncMainBranch` only
- Issue: SOP says "never `reset --hard` in automated flows"; worktree.go violates it with the exact reasoning that was wrong for `syncMainBranch` (two PRs lost on the demo machine before that was caught).
- Fix: Audit every `reset --hard` and `git push --force`; replace with `--ff-only` + explicit divergence handling, OR add a `if !strings.HasPrefix(path, os.TempDir()) { panic(...) }` precondition before destructive ops.

### CS-6. Adapter-level coupling and triplication of polling logic — `[P2]`
- Surfaced by: Stream 1 (P2 `autopilot` imports concrete adapters; P2 adapter→executor coupling), Stream 2 (P2 3 issue pollers with 90% identical structure; P2 7 per-adapter `*_processed` tables)
- Files: `internal/adapters/{github,gitlab,azuredevops}/poller.go` (~3,400 LOC near-duplicate); `internal/adapters/{github,gitlab,azuredevops}/cleanup.go`; `internal/autopilot/state_store.go:65-114` (7 `*_processed` tables); `internal/autopilot/{feedback_loop,telegram_notifier,scope_guard,releaser,auto_merger,ci_monitor,controller,deployer,release_summary}.go` all import concrete `github`/`telegram`
- Root: `autopilot` is the policy layer but holds `*github.Client` and `*telegram.Client` as concrete fields. Each new adapter triplicates ~1000 LOC of poller code and ~100 LOC of state-store boilerplate.
- Fix: Extract generic `Poller[T any]` with `SourceAdapter` interface; consolidate 7 `*_processed` tables into existing `adapter_processed` generic table; convert autopilot's concrete adapter imports to interface-based dependencies (the `Notifier` interface exists at `controller.go:65` — finish the job for `GitHubOperator`).

### CS-7. God objects in executor + cmd layer — `[P2]`
- Surfaced by: Stream 1 (P2 runner.go 4556 lines; P3 cmd/pilot god functions; P3 pilot.go 1500 lines), Stream 2 (Hotspot #1 runner.go single 2,203-line function)
- Files: `internal/executor/runner.go` (4,556 lines, 111 methods, `executeWithOptions` is 2,203 lines), `cmd/pilot/main.go` (2,988 lines, `runPollingMode` ~1,400 lines), `cmd/pilot/commands.go` (2,968 lines), `internal/pilot/pilot.go` (1,500 lines, 43 methods, 35 fields), `internal/dashboard/tui.go` (2,842), `internal/autopilot/controller.go` (2,532)
- Impact: Every test for any executor feature loads the full Runner. PRs touching runner.go produce massive diffs that are hard to review. cmd/pilot wiring is untestable.
- Fix: Extract `PromptBuilder` (partly done), `ProgressTracker`, `RetryOrchestrator`, `MetricsFlusher`, `StageHandler` from controller.go; introduce `internal/startup/` to hold `runPollingMode` body and its three shim types (`storeTaskChecker`, `preFlightJudgeShim`, `storeExecutionSaver`); decompose `Pilot` god struct into per-adapter `Manager` types.

### CS-8. Webhook signature verification gap on 2 adapters — `[P2]`
- Surfaced by: Stream 3 (P2 — explicit Linear + Azure DevOps missing), partly Stream 1 (gateway → adapters/github VerifyWebhookSignature works for GitHub)
- Files: `internal/adapters/azuredevops/webhook.go`, `internal/adapters/linear/webhook.go`
- Issue: 6/8 webhook handlers verify HMAC; these two don't. No signature tests either.
- Fix: Add `VerifySignature` per platform docs (Linear sends `linear-signature` header; Azure DevOps supports basic-auth header); mirror `plane/webhook_test.go` for test coverage.

### CS-9. Rate-limit handling silently bypassed on most GitHub API paths — `[P1]`
- Surfaced by: Stream 2 (P1 retry helpers dead code), Stream 5 (no metric for rate-limit hits), Stream 8 (smart retry default off)
- Files: `internal/adapters/github/client.go:119-164` (`doRequest` has no retry wrapper); `internal/adapters/github/retry.go` defines `WithRetry`/`WithRetryVoid` but only 20 of 51 client methods wrap calls with it.
- Issue: Endpoints like `GetPullRequest`, `GetCombinedStatus`, `ListIssues`, `ListReleases`, `GetTagForSHA`, `GetJobLogs` surface transient 429/5xx as terminal errors.
- Fix: Move retry into `doRequest` itself (wrap the `httpClient.Do` + status-check loop with `WithRetry`); plus thread `metricsRecorder.RecordAPIError` (currently dead code per Stream 5 P1) into the call site.

### CS-10. Documentation completely out of sync with code reality — `[P1]` (composite)
- Surfaced by: Stream 7 (multiple P1s); confirmed by Stream 1 (FEATURE-MATRIX missing recent work); Stream 6 (no incident-class taxonomy)
- Sites: CLAUDE.md says `v2.53.0 | 316 features` (real: v2.149.3); FEATURE-MATRIX.md frozen at v2.53.0; ARCHITECTURE.md frozen at v2.56.0; CLI flag `--autopilot=` documented as primary in 4 places (it's a hidden alias); `pitfall_git_reset_hard_in_automated_sync.md` cites live call sites for a shipped fix; `docs-and-history.md` says "Nextra v2.13.0 + Next.js 14" (real: nextra ^4.0.0 + next ^15.0.0).
- Impact: Every auto-loaded Claude Code session starts with bad ground truth. Operators searching pitfalls find phantom warnings. Doc-driven decisions are made on stale data.
- Fix: Replace prose version/feature counts with `{CURRENT_VERSION}` MDX interpolation; auto-sync via `docs-version-sync.yml` (already exists for `version.ts`); add `resolved:` frontmatter convention for memories + auto-move to `pitfalls/resolved/`; delete Project Structure tree from CLAUDE.md (replace with link); rewrite CLI Flags from `pilot start --help`.

**Stream summary:** Generally well-structured (interface-at-consumer used correctly in poller.go). Three systemic issues: (1) `github` adapter imports `executor` creating mirror-of-mirror coupling held open by `pilot.go` sitting above both; (2) `autopilot` imports concrete `github`/`telegram` instead of interfaces; (3) `cmd/pilot/` contains substantial business logic that should live in `internal/`.

**P1 findings:**

- **[P1] Retry helpers are dead code on most GitHub API paths** — `internal/adapters/github/client.go:119-164`, `internal/adapters/github/retry.go`. See CS-9.

Migrations, multi-row inserts, delete+insert sequences all run as separate `db.Exec`. Fix: `withTx(func(*sql.Tx) error) error` helper.
- **[P1] `time.Sleep` inside poller loops blocks context cancellation** — `internal/adapters/github/poller.go:479,614,633,644`; same pattern in gitlab and azuredevops pollers. After errors the poller calls `time.Sleep(5 * time.Minute)` instead of `select { case <-ctx.Done(): ...}`. SIGTERM may wait up to 5 minutes per stuck poller.
- **[P1] OnPRCreated dispatch path duplicated and divergent** — `internal/adapters/github/poller.go:564-592` (sequential) and `1151-1190` (parallel). The "diagnostic + notify autopilot" block is duplicated verbatim including 4 copies of the TASK-60 marker comment. Future fixes need to be applied twice — exact surface where v2.149 dispatch incidents originated.
- **[P1] `WithOnIssue` legacy callback only used by tests but kept in production API** — `internal/adapters/github/poller.go:172-178` and parallel branch at 1180. Zero production callers. If a future caller wires the wrong option, the autopilot never sees the PR. Fix: delete `WithOnIssue` + `onIssue` field + dead branch.
- **[P1] Goroutine leak risk on context cancel between `wgMu` unlock and `go func`** — `internal/adapters/github/poller.go:1125-1127`. If downstream blocks on non-context-aware operation, Drain hangs.
- **[P1] Issue grace-period unmark is non-atomic between in-memory map and store** — `internal/adapters/github/poller.go:775-785` and `997-1006`. If DB unmark fails, in-memory state diverges from persistent state.
- **[P1] Sequential mode does not refresh labels before dispatch (parallel mode does)** — `internal/adapters/github/poller.go:691-818` (sequential) vs `1069-1084` (parallel does fresh `GetIssue`, GH-2341). Sequential can dispatch an issue that was already marked `pilot-done` between list and dispatch.

- **[P2] `checkForNewIssues` (287 lines) and `findOldestUnprocessedIssue` (128 lines) share 80% of filter logic** — `internal/adapters/github/poller.go:906-1192` and `691-818`.

## 4. Recurring themes

Patterns that crossed multiple streams. These are higher-leverage than individual findings.

### Theme A: Defensive coding instinct favors silent failure

- Streams: 5 (silent skip), 6 (silent disable bug class), 8 (silent env expansion, silent config clamp, silent lint pass), 7 (silent CLI deprecation)
- New gates default to silent `continue`. Env vars default to "use empty string if missing." Config values default to clamping silently. Quality gates default to passing if tooling absent. CLI flag deprecations default to silent alias.
- **Cumulative effect**: Operators see "Pilot stopped" or "the metric is flat" or "this feature doesn't work" without any signal. Average incident-resolution time is high because root cause requires source reading.

### Theme B: Default-off operational hardening

- Streams: 8 (retry, stagnation, subprocess limits, autopilot, alerts, daily-brief, quality, budget all default off), 5 (no panic recovery, no correlation IDs)
- Pilot ships with most hardening disabled. New users get the un-hardened experience; existing users may not realize hardening exists.
- **Cumulative effect**: The 2026-05-21 OOMs, dispatch loss, and quality flakes all happened on configurations that did not have the relevant hardening enabled, even though it shipped.

### Theme C: Triplication at adapter layer

- Streams: 1 (CS-6 adapter coupling), 2 (3 pollers ~90% identical, 7 `*_processed` tables, 6 messengers, 3 cleanup files)
- Each new ticket-system adapter requires ~1,000-3,000 LOC of near-duplicate code. Fixes in github don't propagate to gitlab/azuredevops.
- **Cumulative effect**: 2026-05-21 dispatch fix exists in github poller but not the other two; security-of-the-week (HMAC verification) varies by adapter.

### Theme D: Tests reproduce scenarios, not assert invariants

- Streams: 3 (no `t.Parallel`, no benchmarks, no fuzz, no `TestMain`), 6 (GH-201 needed 2 PRs to add 4 cases for the same predicate)
- The test surface enumerates known incidents. It does not assert "every caller of `CreateSubIssues` validates parent state" or "post-flight notifier and pre-dispatch poller agree on completion."
- **Cumulative effect**: Same bug class keeps regressing. Each fix adds a test for the specific path; the structural invariant remains unstated.

### Theme E: Documentation is prose, not derived

- Streams: 7 (version drift, feature counts, project structure all hand-maintained and wrong)
- Only `docs/lib/version.ts` is auto-synced. Everything else (CLAUDE.md "Current Status", FEATURE-MATRIX, ARCHITECTURE.md, inline `pilot v2.102.2` examples) drifts.
- **Cumulative effect**: Auto-loaded context lies. Memory citations point at fixed code. Onboarding docs teach hidden flags.

### Theme F: Configuration knobs that don't do what the doc says

- Streams: 8 (model routing all-same, releaser frozen at startup, `DefaultEnvironment` never read, `Config.Reload` dead code), 7 (`--autopilot` documented but deprecated)
- Several config fields look meaningful but are inert or only partially wired.
- **Cumulative effect**: Operators tune knobs that have no effect; misdiagnose system behavior.
